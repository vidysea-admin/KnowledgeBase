# T-045 durable source worker

Source jobs are preparation until the current runtime factory, mounted API routes, compiled separate worker and independent fixture/live checks succeed. This document does not claim a working operator installation.

`apps/api/src/source-intake/jobs/store.ts` exports createConfiguredSourceJobs(env): LKB_SOURCE_INTAKE=1 plus absolute LKB_SOURCE_JOB_DIR constructs a private shared journal. The directory parent must exist; root files/directories are owned by the worker/API identity and inaccessible to other users, with no symlinks. Hosting/account/source spool directories must be distinct. Both processes need the same private volume. No canonical Mongo collection or production migration is introduced.

The API passes verified tenantId and actorKeyId, public canonical URL and idempotencyKey to enqueue. Its trusted authorization callback returns approvedBy matching the verified actor plus a nonsecret server approvalRef. Only canonical YouTube, query-free OnAir and query-free Zoom recording URLs are accepted; credentials, fragments, ports, secrets in query parameters, generic articles and watched snapshots refuse. Cookies/provider keys remain worker-only trusted runtime configuration. Client approval/tenant claims do not become authority.

Spool operations now use PrivateSourceJournal with actual verifyPrivateDirectory/verifyPrivateArtifact before root, hashed tenant-directory and artifact reads, and before append. Windows uses the bounded native owner/DACL reader; POSIX uses current uid/private modes. A permissive existing root, tenant directory, audit file or foreign owner refuses before a bearer Zoom URL can be persisted or consumed. The root must already exist and have verified private permissions. Compiled Windows installation additionally needs the current private-acl.ps1 runtime asset; shared bundler now routes static PowerShell assets into dist/runtime-assets, with fresh build/native execution pending. Absence fails closed.

Protected OnAir requires LKB_ONAIR_SESSION_TENANT, LKB_ONAIR_SESSION_ACCOUNT and LKB_ONAIR_SOURCE_BINDINGS. Binding rows contain exactly id, tenantId, accountId, eventId, actorKeyIds, providerProcessing:'approved-recording' and approvalRef referencing actual source-owner permission. All rows belong to that exact session owner/tenant; only explicitly named actors/events can use the account. The API may receive LKB_ONAIR_SESSION_FINGERPRINT (SHA256 of the trimmed authorized cookie header) instead of the cookie. The worker requires the actual cookie and matching current binding. Queue stores private immutable session/binding fingerprints; changes or removal deny execution. Public no-cookie OnAir carries no account proof. Generic worker intake strips the cookie; only the exact approved executeJob constructs a cookie-capable intake. Permission metadata does not establish real login/event/media success.

The privacy basis is D008 provided-first: public recordings retain public mode; caller-supplied Zoom recording and protected owner-approved OnAir retain provided mode. Protected OnAir additionally needs explicit source-owner provider-processing permission. No live meeting/private-span behavior is inferred from this URL-worker path.

API returns202 and safe SourceJobView only: jobId, queued/running/succeeded/uncertain state, revision/timestamps and the completed session/source references. The internal completed() method supplies a narrowed positive indexing receipt for trusted downstream consumers. It never publishes arbitrary provider diagnostics. T053 must verify the physical Mongo/index floor before marking a recording request received; it gates watched sources while immutable snapshot execution is unsupported.

The separate worker rechecks current stored identity/source approval, claims one immutable input and renews a fenced lease. Acquisition, Gemini upload/STT, raw persistence and actual indexing execute outside the journal lock. Only matching version2 complete/index/tree/chunk proof can publish succeeded. A crash, expired lease, lost authorization, incomplete index or uncertain exception becomes uncertain and cannot be automatically replayed. Stale workers cannot publish success. Operator reconciliation requires independently verified durable output; a new approval/key cannot silently reset the old uncertain job. An abandoned journal lock or corrupted append refuses work until owner recovery.

Default API wiring refuses inline SDK transcription. Only explicit execution:'worker' or an injected fixture transcriber composes the old synchronous pipeline. Actual entry.ts and source-jobs.ts factory are authored, with shared bundler output configured but unrun; API entrypoint must remain unchanged and start no bot/transcriber daemon. The worker needs explicit MongoURL/DB, trusted LKB_SOURCE_WORKER_TENANTS allowlist and the source model/native tool configuration. Never invoke this preparation against production or a real provider merely to test it.

Focused jobs.test.ts fixtures use private temporary filesystem journals and deterministic injected intake/index receipts. They cover restart/idempotency/tenancy, positive and incomplete downstream receipts, expiry/crash fencing, authorization refusal, secret URLs and abandoned lock behavior. Ten were authored but unrun when this document was prepared; the sole CPU broker owns execution. They cannot satisfy five actual source runs or cited Ask acceptance.

privacy.test.ts reads all four ISS-T045WORKER-001 and four ISS-T045WORKER-002 reproductions verbatim from the checker shard. Queue protocol tests inject a labeled Windows native-reader snapshot model while retaining physical file checks; that model cannot close Windows ACL acceptance. An attributable actual Windows private-directory receipt remains required separately (native test is skipped without the broker-authorized LKB_T045_NATIVE_ACL_PATH). POSIX private storage is tested through the actual default verifier. These security cases are authored/unrun; no PASS or closed issue is claimed.
