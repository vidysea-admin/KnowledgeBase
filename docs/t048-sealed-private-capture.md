# Captured recording transcription boundary

Captured sources use the actual durable receipt from their confined capture-slot directory. The
source binds the current receipt generation, canonical receipt digest, public masked video bytes,
and audio extracted from that video. Original private media stays an internal artifact reference.
An arbitrary private-window array cannot authorize upload or waive missing speech.

The finalizer invokes the long driver with `--capture-input-fd 0` and bounded JSON stdin containing
version, tenant, session, absolute public audio path, audio SHA256, canonical receipt SHA256,
exact source.json byte SHA256 and actual receipt generation. The child independently checks all
fields and selects only that audio path. Direct captured recovery without the envelope refuses.
Captured transcription requires explicit `LKB_TRANSCRIPT_QA=1`; ordinary provided recordings
retain the existing default-OFF policy. Single-call default promotion remains a separate gate.

Every provider upload revalidates current source, receipt and public media after the actual
provider guard has returned its proof. Provider bytes come from an owned checked audio snapshot;
fallback chunks are extracted solely from that snapshot. Mutated source selection, receipt or
media refuses upload/publication. The new tests intercept provider transport and media commands;
they do not demonstrate real redaction, decoding or a live model result.

Trusted public intervals use the receipt's guarded audio complement. Completeness projects speech
onto accumulated public time, so private windows cannot repeatedly renew missing-speech thresholds.
Protected overlap is removed before public QA and immutable turn publication. Original accepted
provider anomalies remain in a separately bound report, with raw repetition text redacted. Each
attempt records public counts and a reconciled exclusion ledger; rejected attempts are audit only.
QA-repaired turns that newly overlap protected time refuse publication.

`verifyTrustedRecordingPrivacyAdmission` is synchronous for existing consumers. It uses the same
actual receipt parser, generation reconciliation, physical media hashes and public intervals as
the provider path. It also checks current source bytes, QA and turn bytes, duration/count coherence,
accepted raw/public anomaly reports, protected turns and honest coverage. Genuine public deficits
require the validator's explicit partial acceptance. Missing privacy proof never receives it.

The finalizer and loader integrations are owned centrally. This source candidate needs fresh
broker execution and an independent checker verdict. Historical single-dispatch PASS and all
real recording/provider/index/citation/default-promotion gates remain separate.
