# Implementable native producer unit — proposed, not runtime evidence

Scope: Tier 3 / T-042 R3/R4/R7, extending the existing decoded-clock checkpoint. AGENTS.md, the checker skill and the trusted-registry integration clauses were read. No source, contract, dependency, browser, provider, database or test was changed/run. This design is not a checker verdict. Actual usage counters are unavailable; no measured efficiency claim.

## Chosen architecture

Use an owned sample-producing path, not an observer beside MediaRecorder. Keep legacy MediaRecorder recording available but explicitly ineligible for native clock authority. Initially support the existing managed Chromium tab-capture path on a measured browser/build/platform; OBS and unmeasured platforms remain unavailable.

1. In the extension recorder, copy each selected tab image into an owned canvas, with `performance.now()` immediately before and after the synchronous copy and VideoFrame construction. Assign the frame's microsecond timestamp from this producer sampling bracket. Preserve the original source-frame timestamp as diagnostic data only. Record the frame identity, timestamp, bracket and periodic browser monotonic/epoch observations. This proves the local producer-copy time of the actual encoded image, not a remote camera's acquisition time. Source/display latency is a separate applicability uncertainty; do not relabel copy time as source captureTime.
2. Encode those actual VideoFrames with VP8 VideoEncoder, first frame forced key, at existing 1280x720/5fps/500kbps limits. The WebCodecs output algorithm copies each input frame timestamp into the resulting chunk. Track every selected input/output identity; unsupported, missing, reordered/ambiguous, duplicate or discontinuous correspondence poisons the generation. Close frames promptly; cap encode and upload queues.
3. Capture the actual tab PCM in an AudioWorklet; retain block `currentFrame`, channel/sample-rate/count and sequence. Map its sample clock through periodic AudioContext.getOutputTimestamp contextTime/performanceTime pairs. This is the local audio rendering/output clock, explicitly not source acquisition or message-delivery time. Retain raw pairs, suspend/resume transitions, precision and measured residuals. Native qualification requires an independent measured bound for the API's estimated correspondence and A/V latency on the actual supported setup; API existence alone does not establish that bound.
4. Avoid a browser mux dependency: transport encoded VP8 chunks plus bounded PCM blocks to the server-owned receiver. Spool private IVF plus PCM files with quota reservation, bounded queues, sequence deduplication and restart-safe completion markers; do not require Windows FD3 live pipes. A small IVF envelope writer uses explicit 1/1,000,000 timebase and each encoded chunk's actual timestamp relative to the first video timestamp. Existing native FFmpeg reads IVF plus contiguous PCM files, copies VP8, encodes Opus and muxes WebM. The server owns invocation/generation and computes the audio initial offset from the measured audio/video host mappings. Pin exact argv, binary/version/hash, IVF header/timebase and all packet/sample counters. Timestamp-preservation flags are implementation candidates, never proof: verify the produced file independently. No retimestamping from network arrival.
5. Independently decode the completed exact physical WebM using bounded ffprobe `-show_frames -show_streams -show_packets -of json`. Retain rational timebases, decoded PTS/duration/count, first video identity correspondence, audio sample counts, skip-sample/codec-delay metadata, and full decode success. The producer joins the actually decoded first sample to its retained input/chunk/sample identity. Hash media and private evidence only after final close/readback. ffprobe proves decoded timing, not host time by itself.
6. Each real remux/reencode/mask/extraction emits an input/output timing receipt bound to physical hashes and decoder identity. Preserve video PTS/cardinality through scale/mask; explicitly enumerate frame-selection changes if any. Audio mapping accounts for initial offset, sample rate/count, resampling and Opus/AAC priming/discard. Decode both sides; require a unique supported mapping, including selected provider audio zero. Never infer it from duration equality. Compose transformations into the existing finalizer/provider input and root-owned calibration/registry boundary.

Clock equation for a decoded presentation time p: join p to the encoded timestamp x via the independently decoded mux mapping; then evaluate the piecewise measured producer host map H(x). For selected transcript audio time q, compose its measured extraction mapping first. Carry interval uncertainty throughout. Bracket wall-clock reads by monotonic reads; periodically cross-check server monotonic/epoch pairs through a bounded round trip. Clock steps, residual overruns, gaps, source-latency uncertainty or mismatched generations prevent native issuance. No caller-supplied JSON field can select a native issuer.

## Support gates and meaningful fixtures

Preflight secure extension context, canvas VideoFrame construction, VP8 VideoEncoder.isConfigSupported, AudioWorklet, functioning nonzero getOutputTimestamp correspondence, sample format/rate, FFmpeg VP8/Opus/IVF/WebM support, private root/transport authority and bounded queues. Extension manifest minimum Chrome 116 does not prove these capabilities. On failed preflight select legacy capture with fixed native-unavailable; never mint a synthetic calibration.

Offline fixture artifact set under the unit's private temporary root: `source.vp8.ivf`, `source.s16le`, `producer-observations.jsonl`, `mux.webm`, `mux.ffprobe.json`, `public.mp4`, `public.ffprobe.json`, `provider.m4a`, `provider.ffprobe.json`, `transform-receipts.json`, `hashes.json`, `expected.json`. Use small source images with unique test-only frame patterns and PCM impulses at known sample indices; these fixtures are explicitly synthetic and add no production watermark. Cases include nonzero first timestamps, 73ms A/V offset, irregular frame intervals, missing first encoded frame, duplicate/reordered chunks, clock step/drift, audio context suspension, 137ms trim, mask boundaries, AAC/Opus priming, truncated mux, same-name byte replacement and substituted generation. Assert exact first/last decoded PTS, rational mapping, sample count and identity joins; privacy guard must include full held-frame duration and total uncertainty.

Actual-capture acceptance is a separate broker-granted run, never scheduled by this design: exact supported managed Chromium build, server-owned invocation and actual producer path; independently referenced host-timed visual/audio test stimuli on a controlled meeting tab; measured first sample and periodic A/V/host correspondence across the intended duration; sampler-instance bindings; a deliberate clock step/context suspension; real finalization/provider audio and downstream registry readback. Test stimuli belong only to controlled acceptance. Establish numeric maximum uncertainty/drift and sampling-lag applicability before native readiness; no invented universal tolerance. Distinguish synthetic source integration, measured platform qualification and full T-042 real four-panelist/confirmation acceptance.

## Primary sources and evidentiary limits

- WebCodecs, Output EncodedVideoChunks and VideoFrame constructor: https://www.w3.org/TR/webcodecs/ — input timestamp copying and explicit timestamps are standardized; host calibration is not implied.
- MediaStreamTrackProcessor: https://www.w3.org/TR/mediacapture-transform/ — exposes queued raw frames and permits dropping; no standardized source timestamp to host-epoch relation was found in this specification.
- Chrome's encoding walkthrough: https://developer.chrome.com/docs/web-platform/best-practices/webcodecs — explicitly describes canvas-created VideoFrames with application timestamps and separate encoding/mux responsibilities.
- Web Audio getOutputTimestamp: https://webaudio.github.io/web-audio-api/#dom-audiocontext-getoutputtimestamp — the normative context/performance correspondence is for audio output and is estimated; do not claim acquisition-clock accuracy.
- FFprobe: https://ffmpeg.org/ffprobe.html — frame/packet/stream inspection supports independent decoded-timing readback.
- FFmpeg timestamp options: https://www.ffmpeg.org/ffmpeg.html#Advanced-options — timestamp flags interact with muxer/output processing; flags alone cannot certify preservation.
