## What changed

Added the missing `selectNodes -> evaluate -> refine -> answer` pipeline in `packages/ask/src/`,
alongside T-005's existing `evaluator.ts`/`router.ts` (neither modified):

- `packages/ask/src/select-nodes.ts` — `selectNodes(query, tree, complete, treeSearchFn)`: flattens
  the tree (local DFS — see deviation below), prompts the injected `complete`, parses
  `{node_ids: string[]}` (`parseNodeIds`), resolves ids to full nodes via an injected
  `treeSearchFn`. Exports `CompleteFn` and `NodeSearchFn` (both reused by the other new files to
  avoid duplicate type declarations, per `lint-dupes`).
- `packages/ask/src/refine.ts` — `refine(docs, query, complete)`: `decompose` (sentence-split),
  per-strip `complete` keep/drop (`parseKeep`), recompose (join kept strips).
- `packages/ask/src/answer.ts` — `answer(query, refinedContext, sources, complete)`: final
  generation, `sources` passed through by object identity, untouched.
- `packages/ask/src/ask-v2.ts` — `askV2(query, tree, deps)`: composes `selectNodes` -> `ask()`
  (T-005's existing router, which internally calls `evaluate()` — imported, not reimplemented) ->
  `refine` (skipped on a `correct` verdict) -> `answer`. Every LLM call (select_nodes, each refine
  strip, answer) and every per-candidate score is logged via `recordJob` (T-019) into both the
  injected `write` and a returned `auditLog` array.
- `packages/ask/src/testUtils.ts` — shared `fakeComplete`, `fakeWrite`, `fakeTreeSearch` helpers
  used by all four new `*.test.ts` files (packages/ask had no shared test-fake file before this).
- `packages/ask/src/index.ts` — added exports for the five new public symbols
  (`selectNodes`/`parseNodeIds`, `refine`/`decompose`/`parseKeep`/`RefinableDoc`, `answer`/
  `AnswerResult`, `askV2`/`AskV2Deps`/`AskV2Result`/`AuditEntry`, `CompleteFn`/`NodeSearchFn`).
- `packages/ask/package.json` — added `@lkb/ai` as a dependency (needed for `Provider`/`Job`/
  `CompleteResult`/`recordJob`/`WriteJobFn` types). **`@lkb/index` was NOT added** — see deviation.
- `pnpm-lock.yaml` — regenerated by `pnpm install` for the new `@lkb/ai` workspace dependency.

### Deviation from the contract's literal wording — flagged for checker review

The contract (C1) says to "reuse `packages/index`'s tree-walk, do not re-flatten by hand" and
"feed[] those ids to `packages/index`'s existing `treeSearch(tree, node_ids)`" by direct
reference. **This is not possible without breaking an enforced architecture rule.**
`.dependency-cruiser.cjs`'s `ask-index-ingest-only-ai-db-core` rule (mirrored in
`ARCHITECTURE.md` §5: "`ask/index/ingest → ai, db, core`") forbids `packages/ask` from importing
`packages/index` — confirmed by a real `depcruise` failure when I first wrote it that way:
`error ask-index-ingest-only-ai-db-core: packages/ask/src/select-nodes.ts -> packages/index/src/index.ts`.

This repo is under the Lab Protocol (`docs/DECISIONS.md` exists); changing `ARCHITECTURE.md` or
the enforced dependency graph requires a DECISIONS entry + (for enforcement paths) an
Approver's sign-off — not something a maker should do unilaterally to route around a contract
wording issue.

**Fix applied instead:** dependency injection, matching the pattern `router.ts` already uses for
`TreeSearchFn`/`ScoreFn`/`WebFallbackFn`. `selectNodes` takes a `treeSearchFn: NodeSearchFn`
parameter shaped exactly like `@lkb/index`'s `treeSearch(tree, nodeIds)`; `askV2`'s `deps` takes
the same. A real caller (an `apps/*` composition root — which the dependency rules DO allow to
depend on both `ask` and `index`) passes `@lkb/index`'s actual `treeSearch` in. This achieves the
contract's real intent (reuse `packages/index`'s `treeSearch`, never re-implement id→node lookup
inside `packages/ask`) without an unauthorized architecture change. Tests use a same-shape fake
(`testUtils.ts`'s `fakeTreeSearch`) rather than importing `@lkb/index`, for the same reason.

`select-nodes.ts`'s tree-flatten (`flatten()`) is a small local DFS rather than an import from
`packages/index`, because (a) `packages/index/src/tree/search.ts`'s equivalent `walk` generator
is not exported (only `treeSearch` is), and (b) `packages/ask` cannot import `packages/index`
regardless, per above. This is the minimal non-duplicative option available under the enforced
rule, not a re-implementation of anything actually reachable from `packages/ask`.

**Recommendation for checker:** either accept the DI design as satisfying C1's intent (my
reading), or amend the contract to explicitly describe the injected-`treeSearchFn` shape so
future readers aren't misled by the "reuse ... directly" wording.
