## Behaviour
- Row: _id (sha256 of tenantId, sourceId, documentHash, page, charStart, charEnd, quote), tenantId, sourceId, documentHash (= PageIndex.digest), page >= 1, quote, charStart/charEnd (document offsets, independent of page), createdBy (verified keyId), createdAt.
- Store: scopedCollection (tenant merged into every filter) for sources, document_documents, page_highlights, plus a per-row tenant re-check. Page index is built from the tenant's own document_documents row (head-pinned version if sources.sourceMeta.nativeDocumentHead exists, else newest by createdAt) via buildPageIndex. Insert is `updateOne({_id}, {$setOnInsert}, {upsert})`, so repeats and re-ingest are idempotent.
- Route: GET needs scope `sessions`, POST needs `ingest` and a verified keyId. Body keys are an allow-list (tenantId/createdBy in the body = 400). POST runs `validateHighlight` against the index before insert; refusal = 422 with the validator reason. If charStart/charEnd are omitted, the server takes the first verbatim occurrence on the cited page, and validation still decides. Optional `documentHash` mismatch = 409.
- Status map: unknown/foreign/non-document source 404; consent.given !== true, status or head status revoked/deleted 403 (GET and POST); stale documentHash 409; list only returns rows whose documentHash equals the document's current digest, so a changed document never inherits old highlights.
- Consumers: only the new router. The existing web panel (apps/web knowledge/DocumentPageEvidence) reads /knowledge/documents/:id/highlights from document_documents, not this collection; see Not done.
