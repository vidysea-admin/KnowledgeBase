## Acceptance criteria
- **C1 (K1)** Visibility is resolved once per session per request, with batched reads, a per-request memo and a hard deadline. /ask must not load or filter every tenant turn.
- **C2 (K2)** Score candidates first, then check visibility only on the top-k, fetching the next batch if hits are filtered out (bounded).
- **C3 (K5, deadline)** A hard server-side deadline on /search (about 5 s, configurable) that returns 503 with a JSON error code or an empty result (state which and why), never a hang.
- **C4 (K5, cache)** A short-TTL per-tenant result cache keyed on tenant + normalised query + k. It must never serve one tenant's result to another and must be bypassed or invalidated when visibility could have changed (state the rule).
- **C5 (semantics)** Visibility semantics are IDENTICAL (withdrawn, consent-blocked, cross-tenant etc. stay excluded). All existing visibility tests are ported and a regression test per exclusion reason exists on the batched path (ISS-078 class).
- **C6 (measurement)** Before/after is measured on a synthetic ~3,000-turn / ~25-session corpus using the 4 natural questions plus "students", and the numbers are reported here. No live server, no lkb_prod.
- **C7 (K3/K4 decision)** Decide with evidence. If prefilter tokenisation changes, prove recall does not drop.

## The two stated rules
**Timeout (C3): 503 `{"error":"search_timeout"}`, not an empty 200.** An empty `hits: []` is indistinguishable from "the KB knows nothing"; a caller (or the VC) that treats it as an answer would silently drop real knowledge. A 503 with a distinct code lets it retry or fall back. A store-side `VisibilityDeadlineError` maps to the same code; any other failure stays `search_unavailable`. A pending Mongo call cannot be cancelled, so the deadline bounds the CALLER's wait (documented in `withDeadline`).

**Cache rule (C4).** Entries live in `Map<tenantId, Map<key, entry>>` (tenant isolation is structural: `get(A, ...)` can only look inside A's map). The key is `[normalised query (trim, lowercase, collapse whitespace), k]`. An entry is served only if (a) it is younger than the TTL (45 s, `cacheTtlMs`, 0 disables) AND (b) a visibility fingerprint read NOW equals the one stored with it. The fingerprint is a sha256 over the tenant's sources (kind, consent), sessions (sourceId, status), transcript_reviews head revisions and whatsapp_candidates links (four small projected, tenant-scoped reads per cached request). So a consent withdrawal, a source relabel, a new/changed session, a transcript correction or a new WhatsApp candidate link invalidates at once. A failure to compute the fingerprint BYPASSES the cache. A result that touches a session whose source is a whatsapp-batch is NEVER cached (its visibility also depends on per-candidate approvals and claims). What the fingerprint cannot see (appended turns, session title/date) is bounded by the 45 s TTL. Values are cloned in and out.

## Decision (C7): K3/K4 deferred, prefilter tokenisation NOT changed
Evidence: (1) After K1/K2 the cost of a query is no longer proportional to the candidate count (110-130 calls and 50-80 ms at 2,000-3,000 candidates), so shrinking the candidate set buys little on this corpus. (2) The prefilter must remain a superset of the scorer's tokens (ISS-072/075, pinned by search-prefilter.test.ts); the scorer counts stopwords like "the", "in", "for", so removing them from the prefilter changes which turns can score > 0 and therefore changes recall, and the proof of "recall does not drop" would require changing the scorer too, which is outside this unit. (3) Nothing was changed in search-prefilter.ts or the scorer, so there is no recall claim to prove. Known consequence, pinned by a test: `readSearchCandidateTurns` has a 5,000-candidate / 20,000-row / 5 s ceiling (already true for /search); the /ask lexical arm now inherits it, where the old arm scored every turn without a ceiling. Above it the arm degrades VISIBLY (`lexical: ... candidate limit exceeded`), never silently empty. The corpus today is ~3,000 turns; a K3 follow-up (a selective /ask prefilter, which needs a scorer-side change) should land before a tenant passes ~5,000 matching turns. Raised for the coordinator.
