## Fix 1 — validate-session.mjs argument parsing
`args.filter((a,i) => !a.startsWith("--") && i !== at + 1)` with `at = -1` excluded index 0, so a bare session id was dropped and usage printed. ## Fix 2 — db-guard-paths.test.mjs stale literal
Test now asserts the guarantee: sync-session imports and calls `resolveWorkDb({... workDb: MONGO_WORK_DB, env: process.env})`, takes `workDb = route.workDb`, and `isProtectedWorkDbName(workDb, process.env)` throws AFTER the route and BEFORE `connect(..., workDb)`. Behavioural test of `resolveWorkDb` + the shared guard added.
**FINDING for the checker (not a failure):** `resolveWorkDb` itself does NOT refuse protected DB names. It only (a) passes the configured name through unless `testData === true`, (b) for testData requires `LKB_ALLOW_STAGING=lkb_staging` and returns `lkb_staging`. The refusal of protected names (lkb, global_university_db, un-opted lkb_staging) lives in `isProtectedWorkDbName`, applied by sync-session to the resolved name. End to end the guard is not weaker (staging reachable only with the opt-in), but the protection depends on that post-resolve check staying in place; the test pins its order. The guard test was not weakened.
