## Open points (declared, not defects)
1. **The guarantee is "generation order", not commit order, and the doc says so.** No schema change was made: Mongo gives a client no commit-ordered key without a new field (a counter document or a change-stream resume token would be a schema or topology change). The residual window is an insert that is in flight (a stalled writer, a slow database) or a host whose clock disagrees when a consumer reads a later id; the doc gives the consumer rule (dedupe on `id`, resume from a cursor at least a settle period old, 60 s suggested) that closes it under stated assumptions. If a stricter guarantee is wanted, that needs a `seq` field (schema + migration) and is a separate decision.
2. **Replay claim narrowed.** R-40 / the old doc said a replay returns the same ids plus new tail events. With id order a late-committing event can appear inside a replayed range (that is the fix); the doc now says so. `spec.md` R-40 ("cursor-based, at-least-once; consumers dedupe on event id") is still true and untouched.
3. **Legacy ids.** Events written before this change carry stock ObjectId ids (second granularity, random tie-break between processes). They order correctly among themselves by second and before any new id of a later second; same-second legacy/new ties are the historic window and not worth migrating.
4. **Index.** The existing `{tenantId, at, _id}` index is no longer used by `list`; the `{tenantId, _id}` unique index serves the cursor and the order. A `linkId`-filtered page uses `{tenantId, linkId, at}` plus an in-memory sort by `_id`. At current volumes that is fine; changing indexes is a migration and was out of scope.
5. **Real-Mongo test not run.** No `mongod` or `WA_REVIEW_TEST_MONGO_URL` is available in this rig, so the updated real-Mongo paging test is skipped; the fake Db models only equality, `$gt` (string compare) and `$or`, which is what `list` now emits. A checker with a test Mongo should run it.
6. **Clamp after a forward clock jump.** The id generator never goes backwards inside a process, so after a large forward clock step its ids stay at the high value until real time catches up (ordering stays correct, the embedded millisecond is ahead). Accepted.
7. **Consent (D-210):** no consent code was modified, extended or called; no consent event added.
8. **Node modules:** ten `node_modules` junctions were created in the worktree to the main tree's and removed link-only with `cmd /c rmdir` before finishing.
