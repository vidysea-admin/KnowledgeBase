  line: required `{id, feature, event, date, unit, links}`; `event ∈ {planned, shipped, updated,
  removed}`; `reason` (nullable/omittable) becomes required + non-empty via an `allOf/if/then`
  conditional whenever `event ∈ {updated, removed}`. Fits `schema/validate.py`'s existing
  per-collection single-doc fixture loop exactly like the other 10 collections — **no change to
  validate.py was needed** [C1].

  (new) — invalid fixture is a `removed` event with no `reason`, proving the conditional actually
  rejects (not vacuous).

  Schema Draft 2020-12 subset this repo uses (type/enum/pattern/minLength/required/properties/
  items/allOf-if-then). No JS schema-validator package (ajv etc.) is in `package.json` yet; this
  reads `schema/features_event.schema.json` itself at runtime rather than hand-copying its field
  list, so the schema file stays the one definition of shape (ARCHITECTURE §5).

  schema, then `fs.appendFileSync`s one JSON line to `docs/FEATURES.jsonl` (never rewrites prior
  lines); throws with the schema errors (including the missing-`reason` case) on an invalid
  entry, so nothing is written on failure. `readEvents(path)` helper reused by the snapshot.

  <json-file>`) + re-exports `appendEvent` for programmatic/test use [C2].
