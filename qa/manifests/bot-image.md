## Deviations from the survey (deliberate, flagged for the checker)
1. `LKB_RECORD_DIR=/app/raw/webinars` (survey said /data/webinars): run-pipeline-deps.mjs:53 hard-codes `ROOT/raw/webinars` for the registration policy resolver, so a single volume mounted there serves both and avoids a symlink (survey blocker 11: no-symlink private-directory checks). `LKB_BOT_PROFILE_DIR=/data/bot-profile` as designed.
2. Volume `lkb-bot-data` is mounted at /app/data (run-pipeline stateDir `data/webinar-release`, where live-proof.json lives).
3. `LKB_CHROME_NO_SANDBOX=1` is an image ENV default (coordinator note: U2 gates `--no-sandbox` on exactly "1"; Chrome runs as non-root uid 1000 in an unprivileged container). It is also a value-less compose pass-through so the host can override. U2 is not merged in this worktree; until it is, the variable has no effect on sb_join.py (the login-mode Chrome in the entrypoint already honours it).
4. **gws is NOT installed in the built image.** The repo has only the Windows asset (docs/webinar-release.md:105, sha 407705D6...67EC2 for the windows zip); no verified Linux release URL/sha exists in the repo and the task forbids network lookups beyond docker pulls. The gws step skips cleanly when `GWS_URL` is empty (build prints "GWS_URL empty: gws not installed"). Consequence, observed: `BOT_MODE=run` without gws exits at "Configured runtime executable is missing: gws" (fails closed). To enable, build with `--build-arg GWS_URL=<linux release archive> --build-arg GWS_SHA256=<sha256>` (compose forwards `GWS_URL`/`GWS_SHA256` from the shell or .env). HUMAN/follow-up: supply the verified Linux asset. (U4 made the off-win32 default bare `gws`; the image still sets `LKB_GWS_PATH=/usr/local/bin/gws` per survey.)
