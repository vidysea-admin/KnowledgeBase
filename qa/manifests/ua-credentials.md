## Criteria (verbatim from plan.md, "A2 ua-credentials", Dual-trigger: password storage and token secrecy)
- A2-1 `hash` then `verify` round-trips; a wrong password, empty string and 129-char string fail; `needsRehash` is true for a weaker parameter string and false for the current one.
- A2-2 Stored value is PHC-formatted, salted (two hashes of one password differ), contains no password.
- A2-3 Email normaliser: table-driven tests for case, NFKC (`ＡＢ@x` forms), whitespace, control chars, two `@`, over-length; idempotent.
- A2-4 Policy: rejects < 12, > 128, deny-list hits, local-part containment; accepts passphrases with spaces and non-ASCII.
- A2-5 Token generator yields 256 random bits, returns the raw value once, and stores/compares only sha256 with `timingSafeEqual`.
- A2-6 If argon2 is used: dependency exactly pinned, import works in the API container image base (checked by building the image or by a documented `node -e` probe); otherwise the scrypt fallback passes the same tests. Dependency decision recorded (H-4).

## What changed
New files (nothing existing edited except the two dependency files):
- `apps/api/src/user-accounts/password.ts` — `hash`, `verify`, `needsRehash` (+ `PASSWORD_HASH_PARAMS`). argon2id, OWASP first-choice parameters **m=19456 KiB (19 MiB), t=2, p=1, version 0x13**, random salt generated by the library (16 bytes), PHC string. Passwords NFKC-normalised, length 1..128 code points (hash throws RangeError outside it; verify returns false). `verify(null | malformed, pw)` runs a full argon2id verify against a per-process random dummy hash and returns false (UA-11). `needsRehash` is true for non-argon2id, a version other than 19, or any of m/t/p below the current value; false for equal or stronger (never downgrades). The constant-time tag comparison happens inside libargon2.
- `apps/api/src/user-accounts/password-policy.ts` — `checkPassword(pw, {email})` -> `{ok:true} | {ok:false, reasons[]}` with the closed vocabulary `invalid | too_short | too_long | common | contains_email`; `normalizePassword`, `passwordLength` (shared with password.ts).
- `apps/api/src/user-accounts/tokens.ts` — `generateToken()` (32 CSPRNG bytes, base64url, returns `{token, tokenHash}`), `hashToken` (reuses `sha256Hex` from `apps/api/src/hash.ts`), `tokenMatches` (`timingSafeEqual` on equal-length digests, false on any malformed input), `checkTokenRecord` (match AND bound to `(userId, purpose)` AND unexpired AND unused, one generic `false`), `tokenExpiry` / `TOKEN_TTL_MS` (verify 24 h, reset 1 h).
- `apps/api/src/user-accounts/email.ts` — `parseEmail`, `normalizeEmail`, `emailLocalPart`, `hasLoneSurrogate`. Validation and normalisation only; **v1 sends no email (D-206)**. Canonical form: trim, NFKC, lowercase, NFKC, trim; max 254; exactly one `@`; local <= 64; no control/format/line-separator characters (CR/LF header injection refused); no whitespace, `<>(),;:\"[]`; domain without empty labels.
- `apps/api/src/user-accounts/common-passwords.txt` — deny-list data (1,274 entries, lowercase NFKC, `#` comments). Read once, fails closed (throws) if missing or under 400 entries.
- `apps/api/package.json` (+1 line) and `pnpm-lock.yaml`: `argon2` **0.45.1**, exact pin, added with `pnpm --filter @lkb/api add argon2@latest --save-exact`; pnpm's reordering of the whole dependency block was reverted so the package.json diff is one added line.
- Tests: `email.test.ts` (43), `tokens.test.ts` (8), `password-policy.test.ts` (12), `password.test.ts` (13).

Deviations and honest limits (for the checker, see also "Known limits"):
1. **Email form is NFKC, not NFC.** The brief said "trim, lowercase, NFC"; spec UA-2 and the plan acceptance say NFKC (`ＡＢ@x` forms), and NFKC is a strict superset for uniqueness. Spec wins; flagged.
2. **The deny list is a hand-curated 1,274-entry file, not a top-10,000 list.** Network was allowed for the argon2 dependency only, and no list exists on this machine. Format is final; swapping in a vetted top-10k list needs no code change. Because the policy minimum is 12, only entries of 12+ characters (and any entry followed by a digit/symbol run, e.g. `password2026!!`) bite in practice. This is spec's own `[ASSUMPTION]` and is unmet at its stated size: a human item.
3. **Production-bundle gap (not fixed here, not in my file list).** `apps/api/scripts/build.mjs` copies runtime assets only for `new URL("x.ps1", import.meta.url)`; `password-policy.ts` uses the same `new URL("./common-passwords.txt", import.meta.url)` form, so a one-token change of that regex (`\.ps1` -> `\.(?:ps1|txt)`) makes the bundle ship the list. Until then a bundled build throws on first `checkPassword` (fail closed, not open). Owner: A3 (or whichever unit next edits build.mjs); tracked in Known limits.
4. Library emits Argon2 parameters in the order `m,p,t` (not the PHC document's `m,t,p`); parsing is by key so both orders work.
