## Compatibility with lane/rulesweb

Read `joinRulesClient.ts`, `JoinRulesPage.tsx`, `api/client.ts` at 818d768 (read-only). Mismatches: none.
- Header names and quoting: the web sends `If-Match: <etag exactly as received, quotes included>` or `If-None-Match: *`, exactly one, never both (so the 400 is unreachable from the web). The API accepts that form.
- GET body `{ruleSet, state}` and the PUT body (rule set only) are unchanged; PUT success returns `{ruleSet, state}` plus the new ETag, which the web adopts.
- The web reads the ETag through `res.headers.get("etag")`; cross-origin that works only because this lane exposes it and allows PUT and the If-* headers.
- Status handling: the web recognises 412 and 428 by status alone; the API bodies need nothing more. 400/403/503 behave as before.
- Stored-empty set: the API sends an ETag, so the web sends `If-Match` and saves. The web's "no ETag and empty set" path (`If-None-Match: *`) is reached only when nothing is stored, where the API accepts it. A non-empty set with no ETag disables Save (fail closed); that cannot happen with this API. No stuck state found.
