- Stale-upstream success ruling: the reducer accepts a success from the CURRENT attempt without re-checking upstream, and records the input fingerprint that attempt started with. If upstream was invalidated meanwhile, the stage becomes `done` with an old input fingerprint, and validity is defined by fingerprint equality, so `planNext` classes it invalid (`input-changed`) and never `complete`: accepted-then-invalidated. No reachable state is `complete` or has a downstream planned over a mismatching fingerprint. Within events alone upstream cannot change (a valid done stage cannot restart), so this only arises after an external source change. Late success from a superseded attempt id is rejected (`stale-attempt`) and does not mark done. Raw state can hold a done stage with a stale fingerprint after a source change; consumers must go through `planNext`, not read `status`. Note for the adapter slice.
- Optional ruling: `optional` means only that a caller may emit `stage-skipped` while the stage is ready; the planner never skips by policy. Terminal failure of `screen` fails the run, and a terminal stage cannot then be skipped. The skipped stage's output is the constant `skipped`, so it is in the downstream fingerprint; but a skipped stage cannot be re-run through events, so "producing it later invalidates index" only works via a state edit. Real runner: `--process-video` is an optional flag, and on screen failure the runner throws and keeps the recording for retry, so the model matches reality; the skip-then-produce path is a note for the adapter slice.
