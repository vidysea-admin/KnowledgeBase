Unreadable lock never reaches the 30 s age rule. Wait budget: every contention branch passes through `backoffOrConflict()` which checks `waitMs`; the only unbudgeted `continue` is `seen === null` (lock vanished between create and read), which is progress, not a spin on a persistent condition. A permanently unreadable lock gives `conflict` after waitMs (known, ISS-JOBQEPERM-001, low).
