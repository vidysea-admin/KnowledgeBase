## Operator rules to document wherever the service is deployed
- One hostname and one PID namespace per state directory (P1); the host refuses to start otherwise. Violating it can lose acknowledged writes.
- Never delete or rename a `.lock` file by hand while any writer may be running; stop the writers first (P4).
- An abandoned `<lock>.claim.<token>` blocks takeover of that one dead lock only. Read the claimant pid from the claim; if that process is gone, delete the CLAIM file only (not the lock). An empty claim is a failed claim write. (P5)
- A backward clock step delays recovery of locks written before the step by up to the size of the step.
- `locked` messages carry file paths: log them for operators, never return them to clients (the API already does not).
