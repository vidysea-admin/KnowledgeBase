# T-055 — Read-only evidence directory slice

Checker-owned criteria for a bounded T-055 contribution. Catalogue A6/B9/B10/B12/B13 and TASKS T-055 describe broader document/page evidence, topic and speaker profiles, curated collections and program directories. This slice exposes only the already accepted sessions/sources/graph read endpoints. It cannot graduate those broader features or close T-055.

- **C1 — Integrated reads.** Actual App router and navigation mount `/knowledge`; the page consumes existing authenticated `GET /sessions`, `GET /sources`, `GET /graph` clients. No new backend, credential transport, data writes or fixture-only route.
- **C2 — Evidence provenance and producer compatibility.** Entity relationships retain actual graph type/origin/evidence IDs. Transcript links require exactly one known returned session, supported by explicit edge/evidence ownership or an unambiguous incident session ref. Conflicting explicit ownership or incident session ownership refuses the link; missing/unknown ownership remains inert. Never derive ownership from labels, slugs, transitive neighbors or positional coincidence. Exercise the actual `buildKnowledgeGraph` producer output independently. Links encode raw session/turn IDs and match the existing session detail anchor consumer; a reference is not a claim the turn was independently verified.
- **C3 — Inference and identity.** Returned inferred relationships remain visibly inferred; graph person labels do not certify speaker identity, organization roles, or full speaker profiles. Preserve graph origin and recorded confidence when present. Render labels as text.
- **C4 — Derived collections.** Group sessions only by valid recorded month; missing/invalid dates have an explicit unavailable group. Clearly distinguish derived read views from saved curated collections. No invented sessions, membership or completion.
- **C5 — Safe resources.** Project recorded source metadata without exposing `source.path`. Public links accept only absolute safe http(s), reject controls/surrounding whitespace and credentials, and use `noopener noreferrer` for new tabs. Missing/unsafe URLs remain inert. Metadata does not prove ingestion or a quality score.
- **C6 — Honest failure and coverage.** Unauthenticated/loading/error/empty/missing selected entity states are usable. Graph 404 preserves sessions/resources with explicit absence; other errors and malformed consumed shapes cannot become successful empty or partial data. Display bounds identify truncation, and counts describe returned records rather than complete corpus or extraction quality. Selection changes reflect the current graph.
- **C7 — Tenant/auth lifecycle.** Existing API key flow applies to all reads. Rotation/logout immediately fences prior authenticated content/errors; late obsolete promises, unmounts and refresh generations cannot replace current data. No credentials in URL links. Unauthenticated mount makes no request.
- **C8 — Focused verification and consumer.** Model/page tests cover positive/negative ownership, inferred/stated rendering, derived collections, safe resources, malformed/error/404/empty cases, auth and obsolete responses. At least one independent behavioral probe checks actual producer output. Actual App/Nav integration and session anchor consumer are reviewed and exercised through focused integration tests; successful web typecheck/bundle evidence and `contracts/verify_contracts.py` are required. Immutable attributed maker/integrator output may be reused when command, result, cycle and final-file pins are clear. Vacuous verifier is disclosed. No browser, DB/provider calls or full suite.
- **C9 — Frozen scope.** Manifest slug/cycle, new knowledge files and shared integration/dependency pins must match final bytes before verdict. Changes outside maker/integrator authorized ownership, protected governance, source corpus/gold, backend/auth/common API behavior are excluded. PASS certifies this complete slice only; page-level document highlights, authoritative entity promotion, full topic/speaker profiles, saved collections, program semantics, live operation and overall T-055 remain unproved.

Not an issue-fix unit; no ledger reproduction corpus is substituted. Any new finding goes to root for serial issue allocation. Security findings are never capped; this directory seam has no prior PASS.
