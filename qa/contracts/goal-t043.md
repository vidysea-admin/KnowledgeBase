## Acceptance

1. **Real input and honest provenance.** Identify the real webinar artifacts, input hashes, source/session/tenant IDs and selected corpus before execution. Run the supported `node scripts/webinar/sync-session.mjs <sessionId> --index` path over a real webinar. Preserve validation and derivation guards. D-149 permits explicit `--legacy-unbound` staging seeding of the existing TOC transcripts, labelled as such, without forged binding; it does not silently exempt other artifacts from provenance validation.
2. **Guarded isolated writes.** All live writes explicitly name and assert `lkb_staging`, per D-143/D-146, never production `lkb`. No credentials appear in evidence. Record the real provider/model, configuration and cost. A different isolated runtime/database must have explicit applicable authorization. Real provider calls and Mongo readback are required; fakes alone are insufficient.
3. **Complete supported indexing.** Actual production indexer invocation succeeds without a temporary replacement tree, injected fake embedding/generation, or skipped required stages. Mongo readback establishes the selected session's turns, session page, claims stage, nonempty chunks with valid compatible vectors, tenant tree membership and successful index status. A strict completion proof must match current input bytes. An empty claim result is acceptable when grounded extraction legitimately found none; degradation is not completion.
4. **Corpus accounting and across-webinar retrieval.** Account for the selected corpus as seen, processed, rejected or pending, retaining explicit reasons. The real tenant tree must include the successfully indexed real sessions; indexing another webinar must preserve prior sessions. Ask at least two session-specific questions over two real webinars through one tenant's actual API, with correct respective session evidence. Record the remaining original TOC/staging gaps; partial indexing must never be represented as complete corpus coverage.
5. **Real /ask downstream consumer.** Start the actual API with production dependencies and authenticated tenant identity, and POST `/ask`. At least one useful internal answer is supported by the just-indexed real session; a second question establishes the across-webinar behavior in C4. Retain exact command, HTTP status/body, provider receipt/job evidence and output artifacts. Demonstrate that the vector arm operates against persisted compatible embeddings, as well as the production tree path. A quota failure with tree-only fallback does not prove the vector arm.
6. **Exact citations.** Every returned internal citation resolves under the requesting tenant to its real session and turn. Verify session/turn identity, speaker, finite ordered timestamps, exact quote character bounds and turn-text hash where supplied. The cited quote must support the substantive answer; source text or an uncited generic answer alone is insufficient. Web evidence, when used, remains separately identified.
7. **Tenant boundaries.** Auth determines tenant; body/query/header tenant selectors cannot widen it. Exercise the actual Mongo-backed API with a second tenant, including conflicting IDs or higher-ranked bait where feasible, and an empty/no-tree tenant. Foreign data must not enter response, model input, audit/job output or persisted indexes. Review the production read/write filters and rerun the focused hostile/isolation probes; the existing fake-DB PASS is supplementary rather than proof of real composition.
8. **Idempotency and failure integrity.** Repeat supported sync/index on the real fixture: stable natural IDs/content hashes prevent duplicate source/session/turn/chunk/tree membership and preserve unrelated tenants/sessions. Record counts/hash evidence. Required provider failure, invalid new timing or stale proof must not emit success/completion. Use focused existing checks for these boundaries; do not mutate production data.
9. **Invalid legacy source rows.** Apply D-153: invalid legacy turns are excluded individually with a warning and never cited; valid remaining sessions remain answerable. All-invalid source context refuses, and foreign tenant/session rows refuse the whole request. New invalid timing is rejected before knowledge writes. Verify affected production code and focused behavioral evidence, rather than silently removing whole sessions from the proof corpus.
10. **Independent, current evidence.** Provide a ready-for-check manifest/packet with fix cycle, exact changed and relevant dependency hashes, command invocations, duration/exit/counts and persisted artifacts. Checker rechecks final bytes, independently probes affected behavior, runs `contracts/verify_contracts.py` when applicable, and verifies downstream consumption. Any required evidence absent or blocked means HOLD; a reproduced violation means FAIL. Only a checker PASS for this full scope permits parent completion.
