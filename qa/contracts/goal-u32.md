## Required criteria

1. **C1 — Integrated global entry and Search.** The actual composed signed-in app renders one global search bar on its main routes, including dashboard, sessions, Ask, calendar and Search. Signed-out state exposes no authenticated search results/request. Keyboard Enter and button submission reach /search?q= with the same normalized query. Blank input makes no request. Existing explicit-page search continues to work.
2. **C2 — URL and state correctness.** A nonempty direct URL executes the intended lexical search once per distinct query, same-query retry works, and browser Back restores the previous query/results. Query text is decoded once, bounded to 512 code points and safely displayed; Unicode, %, &, #, hostile markup, controls and malformed encoding do not execute code or crash app routing. Editing alone makes no retrieval call. Key/query changes hide previous results immediately and late responses/errors cannot restore stale tenant data.
3. **C3 — Authenticated tenant-scoped lexical integration.** The real Search client reaches the mounted real GET /search route with bearer authentication and no client-selected tenant. Only the authenticated tenant's evidence appears. Invalid authentication and missing search scope expose safe sign-in/access messages and no results. Loading, no-hit, retry and unavailable states are explicit. Client response validation rejects inconsistent identities, nonfinite intervals/scores, duplicate identities and malformed joins without fabricating evidence.
4. **C4 — Exact lexical evidence and downstream navigation.** Results show actual session title/date, literal passage, actual speaker label/ref and time range (document/URL character offsets labeled correctly). Open transcript uses the returned session and exact turn identifier. The actual SessionDetail consumer reveals and highlights that turn, including turns after index 200, with quote/speaker/time intact and bounded rendering. Null/missing source joins offer an unavailable state rather than an invented citation/link. Back returns to the submitted query. Existing media seeking remains functional.
5. **C5 — Ranked retrieval visible and honest.** The Search page consumes real meaning-based or hybrid ranked retrieval from its supported mounted backend (consistent with its U1.5 foundation), rather than merely showing lexical results under a semantic heading. Explicit semantic invocation is allowed and must not dispatch paid embedding calls on mount/edit. Ranked hits retain verified chunk/session identities, score semantics and available provenance, including quote turn id/text/character offsets, turnIds and finite ordered time interval. A source link opens the exact returned quote turn; a session-only legacy response is labeled as such rather than asserted to be an exact passage. Invalid/inconsistent provenance fails safely. Disabled/unavailable provider/backend states are honest and do not count as successful live ranked retrieval. Retrieval score is not displayed as answer confidence.
6. **C6 — Send to Ask and actual consumer.** The Search workflow offers Send to Ask carrying the submitted normalized question to the actual /ask page. The Ask input receives it without silently calling POST /ask. Explicit Ask submission uses the current authenticated key and the existing answer/citation workflow. Unicode and special characters round-trip once; untrusted URL text is bounded/inert. Query/key changes cannot expose a previous identity's late answer/error. Missing Ask scope is handled without leaking evidence. A handoff link alone, with no working Ask consumer, does not satisfy this criterion.
7. **C7 — Complete UI verification.** A real authenticated browser walk covers the umesh-operator and external-developer personas named in docs/plan.md: global entry, lexical and ranked results, citation navigation, Ask handoff and submission, Back/retry, unavailable/auth/tenant boundaries, keyboard access and mobile layout. Capture actual network/DOM/source evidence and console errors with candidate/runtime identity. Existing 2026-10-13 Chrome evidence is reusable only for its tested bytes and covered lexical behavior; it explicitly left ranked retrieval and Send to Ask untested and was not the required persona walk. The known Vite malformed-percent HTTP 500 is disclosed and evaluated against the actual served target, without silently counting it as app success.
8. **C8 — Evidence and closure.** A matching ready-for-check manifest names the exact cycle, source/dependency map, final hashes, contract clauses, focused commands/results and actual sample fixtures. Independent checker source review and focused behavioral probes cover changed and security boundaries. The affected stage and immediate downstream API/Session/Ask consumers run green; contracts/verify_contracts.py passes when applicable. Final bytes are re-pinned before verdict. Full-parent PASS requires C1–C8 and a completed U3.1 dependency; missing real auth/provider/browser/host evidence yields HOLD, a proven acceptance violation yields FAIL. Root owns tracker updates and any final Approver closure; scoped PASS is never upgraded by assumption.
