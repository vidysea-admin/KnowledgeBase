## Criteria

1. **Actual producer/consumer regression floor.** Preserve the original producer/finalizer bytes and the actual six-case RED receipt. The regression floor must invoke the exact current sync CLI proof-producing block with the real prepared proof helper and retention writer, then the actual exported capture validator. Synthetic completed-index input is permitted only at the declared boundary. Never relabel the current producer's v3 output as v2 to pass the compatibility case. The unchanged six-case floor must consume valid combined and passed speech-only v3 outputs after repair; retain exact commands, counts, timing and pins.
2. **V3 source, session and database binding.** Refuse a wrong proof tenant/session/source ID, changed source hash, independently mismatched configured database or production database. Require current session metadata matching session/tenant/source and done transcription/index status. A testData source stays staging-only even when caller and proof agree on another database. The configured expected database must come from the consumer caller/environment, never the proof.
3. **Current selected input and gates.** Accept only literal turns.json or knowledge-turns.json. Require a nonempty record-array, exact safe-integer turn count and current byte hash. Speech input requires passed transcript validation with the same hash; combined input requires a done video stage with its selected output hash. Core completion requires strict/done/semanticSupport and all four done stage fields, plus a nonempty string generation. Stale, missing or failed gates and incomplete core states refuse.
4. **V3 hostile row guards.** Even with rewritten matching input/gate hashes, refuse foreign-tenant/session turns, duplicate/empty identities, empty speaker/text, nonfinite or negative starts and reversed timing. Preserve and pass the four added identity/gate probes as well as the original six-case floor. These deterministic checks do not prove media accuracy, authentic provider execution or cryptographic provenance.
5. **Narrow and safe consumer implementation.** Existing capture-file changes are restricted to importing the typed consumer and delegating validateIndexProof with its optional independently expected database. Preserve the surrounding provider/privacy/finalization flow. The new consumer uses guarded unknown JSON values, fixed file names, bounded safe read-only snapshots and final unchanged-byte checks. No any, compiler/schema/guard weakening, outbound call or data mutation is introduced. Review the actual read dependency and immediate caller.
6. **Legacy limitation is explicit.** Legacy v2 combined proofs remain accepted with their existing core tenant/session/hash/stage checks and strengthened count/string-generation checks. V2 does not acquire v3 source-ID/source-hash/database/session-status/selected-row/gate guarantees. This unit does not prove rejection of manual downgrade attacks or authenticated proof provenance; these limits must be stated in manifest, packet and verdict. Do not claim them as tested security guarantees.
7. **Current handshake and evidence.** Matching slug manifest/packet must be ready-for-check at an explicit fix cycle. Reuse the actual 10/10 replay only when all nine source pins still match before verdict, and inspect the preserved RED and GREEN stdout/receipts. Separate independent source/hash review from attributed execution. A changed candidate needs resubmission. No duplicate execution is required merely to credit a valid unchanged receipt. Only checker may PASS this scope; parent T-043 remains in_progress.
