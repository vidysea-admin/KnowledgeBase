# Acceptance — T-022 local offline human review

Checker-owned new source unit `goal-t022-offline-review`; T-022 roadmap tier 3. Existing `goal-t022` source PASS cycle 0, its fourteen candidate files and the old static review HTML remain separate and unchanged. This unit makes the current thirty neutral inputs locally reviewable; it does not authenticate a person, create human gold, write the protected server store or close T-022.

## Criteria

1. **Current packet, not a substituted corpus.** Before generating a new HTML artifact, regenerate/check the current neutral packet against its golden/rival selection, source bytes and production judge inputs. Exactly thirty distinct IDs, fifteen expected/rival question pairs, three batches of ten and the existing conservative 0–1 rubric are preserved. Bind tenant, neutral packet JSON-value SHA-256, all source paths/byte counts/hashes and each exact query/title/summary input digest. Refuse source/packet drift before creating output. The current reference has thirty neutral items and forty-four bindings; no historical proxy scores or AI labels populate the form.
2. **Actually usable offline.** A standalone local HTML file embeds all required data, controls, styling and code. It shows every full query, title and judge-visible summary, item/batch identity, existing rubric, pending/submitted progress and review-only node identity. Each item can be selected, scored with a finite number in [0,1], given a nonempty rationale and individually affirmed as personally reviewed by Umesh. Labels, keyboard controls and long text are usable. No network, API key, DB, provider or remote asset is required. All corpus text is rendered literally without script/HTML execution, including closing-script payloads and dangerous markup.
3. **Thirty initially neutral judgments.** Every initial score/rationale/reviewer/time is null or an equivalently explicit unset local draft value; affirmation is false and local revision is zero. A checked implementation, opened file, click-through or model/fixture never supplies a judgment. There is no approve-all, inferred score, batch affirmation or automatic human-gold promotion. Saving one item never fills another. Browser time and typed Umesh assertions are expressly unauthenticated.
4. **Individual validation and local revision.** Save requires a nonblank numeric input, finite score in range, nonblank bounded rationale and fresh explicit affirmation for that item. The exact current input digest and item ID are bound. Accepted individual changes advance that item's local revision; changing a saved score/rationale cannot silently retain its prior affirmation. Invalid saves do not advance revision, submitted count or success state. Distinguish `localRevision` from server CAS: without a current authenticated server view, `serverExpectedRevision` is null; never invent a server revision or audit actor.
5. **Resume without stale approval reuse.** Local draft persistence is namespaced by format/tenant/neutral-packet digest. Resume validates complete structural identity, known distinct IDs, per-item digests, numeric/rationale/affirmation/revision consistency and count derivation. Missing, malformed, foreign-tenant, foreign-packet or altered-input state cannot become effective judgments. Storage unavailability or failed persistence is visible; the UI must not claim durable saved/resumable state after failure. The person can still review/export in explicitly disclosed memory-only mode when browser local-file storage is unavailable. If local draft JSON import exists, it uses the same validation and cannot import authoritative approval claims.
6. **Draft export is an explicit separate format.** Downloaded JSON has a format distinct from `calibration-reviewed-export-v1` and `calibration-human-references-v1`, for example `calibration-offline-draft-v1`. It includes packet/source/input bindings, each item's local judgment/revision and null unknown server revision, honest pending/submitted counts, `humanGoldVerified:false` and an explicit non-authoritative-server-audit marker/limitation. It supplies no authenticated actor, synthetic server audit or verified-human receipt. A partial draft may be exported only when pending entries stay visibly pending; a complete draft requires thirty individually valid affirmative local judgments. Export preserves the exact entered fractional scores/rationales and cannot overwrite repository corpus, neutral seed, existing protected review state, previous static HTML or historical results.
7. **Accepted-format boundary remains closed.** Feed the actual exported draft to the existing `validateHumanCalibrationInputs` boundary: it must refuse before provider access because it is not an authoritative stored-review export. Local judgments must not be relabeled as authenticated approvals by the offline generator, HTML, export or test harness. Source inputs in acceptance checks remain the authentic current private packet/corpus; entered judgments and adversarial modifications are explicitly fictional test values, never actual Umesh evidence. No substituted synthetic corpus may stand in for required authentic input checks. No new trusted receipt or operator hash is generated/configured by this unit.
8. **Current-source authenticated transfer remains a real gate.** Run instructions identify the source-bound offline artifact and the existing protected authenticated review workflow. Before any future transfer, an operator must revalidate the neutral packet and all current sources; reconcile each actual Umesh judgment/input digest; obtain a current tenant-authenticated view and its item CAS revision; and submit/affirm each item through the authorized protected route or separately accepted import. Offline draft data alone cannot assert that this happened. The authoritative export and thirty genuine owner confirmations then require independently checked evidence and an operator-pinned verified-human receipt before any model run. The configured receipt digest is SHA-256 of `JSON.stringify(parsedReceipt)`, not raw file bytes. D-164 model predecessor order and all full T-022 live/provenance/application gates remain binding.
9. **Bounded generation and preserved artifacts.** Generator writes only a separately named new offline HTML under its lease using exclusive-create or equivalent no-overwrite semantics after validation. Re-running refuses an existing target rather than clearing human work. It never changes source snapshots, raw media, old `t022-review-package.html`, the original fourteen source files, thresholds, production routing or external state. Its CLI validates required options and returns a visible failure without a misleading success artifact.
10. **Independent source evidence, no synthetic human completion.** Matching ready-for-check manifest/packet/cycle and final hashes identify helper, tests and new artifact. Meaningful execution goes through the sole `/root/docker_governance_review` broker, with bounded commands and immutable receipts. Authentic private input checks require the literally configured `KB_T022_PRIVATE_REVIEW_TESTS=1` under the explicit local-only authorization; default skipped/HOLD tests cannot count as PASS. Private HTML generation occurs only after the authorized authentic checks pass; artifact/drafts remain local and excluded from publication. Focused pure/DOM checks exercise actual generated controls and downstream draft refusal: all thirty exact neutral inputs, one fractional fictional save, invalid/blank/out-of-range refusal, independent items, amendment re-affirmation/local revisions, save/resume, corrupt/foreign/drifted storage refusal, unavailable/failed storage, literal hostile text, honest partial/complete export and existing output/source preservation. No browser calls, DB/provider/network/full suite or repeated prior 17/DOM4/46 checks. A source PASS certifies only this offline capability; actual human reviews remain 0/30 unless real evidence exists.

## Scope and current gaps

Offline HTML can make the judgment task usable without an evidenced live application, private server configuration or tenant credential. It cannot substitute for them at authenticated transfer or final calibration. Current real owner judgments, server-transfer evidence, independent owner-verification receipt, executed-provider provenance, live calibration and deployed human UI acceptance remain separate full-task gates. Makers never edit this contract or checker verdict; historical evidence remains attributed to its original scope and bytes.
