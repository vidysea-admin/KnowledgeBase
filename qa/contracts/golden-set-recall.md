# Contract — golden-set-recall (T-021)

> Ground truth for the retrieval golden set + recall@k report, per plan §4c D7/§6c.3 evaluation
> plan and TASKS.md's own text ("Golden set (50-100 Qs) + recall@k report, target recall@5 ≥
> 0.85"). Drafted by the maker; /checker adopts or amends on first check.

## Scope, and an honest scope-down disclosed up front
The plan's full design (§6c.3) is: 50-100 human-confirmed Qs, evaluated through the REAL
retrieval pipeline (`selectNodes`'s LLM call, `packages/ask`). That pipeline's only LLM path is
currently blocked — **`GEMINI_API_KEY` in `.env` is invalid (ISS-015, same root cause blocking
T-003)** — so a live end-to-end run against the real LLM cannot execute in this environment right
now. Rather than fake a "recall@5 = 0.85+" number against a system that cannot actually run, this
unit builds the injectable, real-by-default-but-fakeable HARNESS (same seam pattern as every
provider/adapter in this codebase) plus a real golden set derived from actual migrated TOC
content, and reports recall@5 using a heuristic (non-LLM) retriever as the default — a
lower-rigor but honestly-labeled proxy for retrieval quality, not a substitute for the real
`selectNodes` pipeline. **Running this harness against the real LLM retriever, once ISS-015 is
resolved, is the natural follow-up (T-022 already exists for evaluator calibration; this report
should be re-run then, not treated as final).**

## Criteria (each machine-checkable)

1. **Golden set is grounded in real content, not invented**: `data/eval/golden-set.json` — an
   array of `{id, question, expectedSessionId}`, generated by `scripts/gen-golden-set.mjs` FROM
   the real `data/toc-migrated/*/session_page.json` `keyInsights` (verbatim excerpts, not
   paraphrased/hallucinated) — every `expectedSessionId` must correspond to an actual directory
   under `data/toc-migrated/`. At least 30 questions, spanning at least 15 of the 23 real
   sessions (proving coverage, not just volume from a few sessions). Script must be idempotent
   (re-running produces the same output for the same input data).
2. **`packages/index/src/eval/recall.ts`**: pure, injectable `computeRecallAtK(questions,
   retrieveFn, k)` — `retrieveFn: (question: string, k: number) => string[]` (ranked session ids,
   caller's responsibility to rank; this function only checks membership within the top-k).
   Returns `{recallAtK, k, total, hits, misses: [{id, question, expectedSessionId, got}]}` — every
   miss is named, not just counted (auditability, matching the evaluator's own per-candidate
   reason discipline in `packages/ask`). No I/O, no network — pure computation over injected data.
3. **`packages/index/src/eval/heuristic-retriever.ts`**: `createHeuristicRetriever(tree):
   RetrieveFn` — ranks a tenant's session nodes by keyword-overlap between the question and each
   session node's `summary` (same bag-of-words technique as `apps/api/src/score.ts`'s
   `heuristicScore` and `extract-topics.ts`'s heuristic — reuse the pattern, not necessarily the
   code, since they operate on different shapes), returns the top-`k` `evidence.sessionRef`
   values ranked descending by score. Explicitly disclosed in its own doc comment as a
   NON-LLM proxy, not `packages/ask`'s real `selectNodes`.
4. **`scripts/eval-recall.mjs`**: loads the real golden set + builds the real tree from
   `data/toc-migrated/*` (same `tsx/esm/api` `register()` pattern as `scripts/seed-toc.mjs`),
   runs `computeRecallAtK` with the heuristic retriever at `k=5`, prints the recall@5 score and
   every miss, and writes `data/eval/recall-report.json` (`{generatedAt, k, retriever:
   "heuristic", recallAtK, total, hits, misses}`). No live network call, no live Mongo — reads
   only local files, same posture as `scripts/seed-toc.mjs --dry-run`.
5. **Tests exist and pass**: `packages/index/src/eval/recall.test.ts` covering
   `computeRecallAtK` with fake questions + a fake `retrieveFn` (hit, miss, and a mix — asserting
   the `misses` array is correctly populated); `packages/index/src/eval/heuristic-retriever.test.ts`
   covering the retriever against a small synthetic tree (fixture sessions with distinct summaries)
   proving it ranks a matching session above a non-matching one.
6. **The script actually runs and reports a number** (not just typechecks): `node --import
   tsx/esm scripts/eval-recall.mjs` (or the exact invocation the script needs) exits 0 and prints
   a `recallAtK` value; whatever that value is gets reported honestly in the manifest — this
   criterion is about the harness executing end-to-end on real data, NOT about hitting the 0.85
   target (that target is explicitly deferred to a real-LLM re-run per the Scope section above).
7. **No regression**: `pnpm -r typecheck`, `pnpm -r test`, `pnpm gen:types --check`,
   `python schema/validate.py`, `pnpm lint:structure` all clean.

## Non-goals for T-021
- No live LLM call anywhere in this unit (blocked on ISS-015). No claim that recall@5 ≥ 0.85 is
  proven against the real system — only that the harness exists and reports an honest number
  against a heuristic stand-in. No wiring into `apps/api`'s `/ask` route (this is an offline eval
  script, not a production code path). No T-022 (evaluator calibration) — that is a separate,
  later unit that depends on this one's golden set existing.
