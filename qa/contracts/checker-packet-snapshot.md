## Acceptance criteria

- **C1 — Explicit, contained ownership.** Snapshot requires caller-supplied workspace root, exact source allowlist and a new owned output directory beneath the workspace's designated cache. Refuse absent/empty or ambiguous ownership, duplicate/case-alias entries, absolute/drive/UNC paths, traversal, noncanonical aliases, escaping source/output paths, redirected source/output ancestors or files (including symlink/junction/reparse redirection), directory/device inputs and credential/storage paths. Reject known private credential/config roots and `.env` files/variants; this does not prohibit source code that implements authentication. Validation precedes writes. Keep all created output inside the owned cache directory; no source write, external cleanup or arbitrary directory replacement is allowed.
- **C2 — Before-edit exact bytes and honest absence.** Snapshot captures existing source bytes without EOL/BOM/Unicode normalization and records their SHA256/base-existence, path and actual timestamps. A genuinely absent allowed source has explicit `baseExists:false`/missing-base state, never a fabricated empty-file baseline. Preserve raw CRLF and UTF8 BOM. The artifact says when capture occurred; it does not retrospectively reconstruct a pre-edit baseline from final sources or another checkout. A later-created source can freeze against its genuine missing baseline.
- **C3 — No overwrite, atomic completion and drift refusal.** Snapshot/freeze refuse existing destinations and existing snapshot members rather than replacing them. Reserve ownership exclusively and publish a complete operation atomically or expose an explicit incomplete/refused state that cannot be treated as a frozen packet. Concurrent same-destination attempts cannot overwrite the winner. Compare source existence/raw hashes before and after capture and before/after freeze; observed drift, changed base backups or unexpected creation/removal refuses completion. Failure/interruption may leave only owned identifiable incomplete cache artifacts, never a plausible successful inventory or modified source. Cleanup cannot follow redirections or remove unrelated data.
- **C4 — Full freeze inputs, real formats.** Freeze binds slug/cycle, snapshot/base pins, final sources, unchanged dependency/evidence lists, an explicitly expected immutable contract digest and required command receipts/output digests. Consume both actual CI `sources` rows (`baseSha256`, `baseBackup`) and B7/D3 `entries` rows (`baseExists`, `baseSha256`), with explicit documented adapters or one unambiguous canonical form. Reject ambiguous mixed shapes, omitted required groups/fields, invalid hashes, duplicate/overlapping identities and unowned/inconsistent baseline references. Hash every required input/output and verify supplied digest expectations; omission cannot manufacture a complete packet. Preserve exact source/dependency/evidence/contract pins and truthful missing-base provenance; do not rewrite accepted inventories or contracts.
- **C5 — Receipt/output integrity and bounded work.** Required receipts retain exact argv/cwd, observed start/end timestamps, duration, integer exit result and exact output path/hash; expected nonzero RED receipts can remain explicit rather than being silently converted to GREEN. Missing receipt/output, changed output digest, malformed timing/count/hash/path data or conflicting records refuses freeze/verification. Enforce explicit finite limits on row counts, bytes per source/receipt/inventory, aggregate bytes and compact diagnostics, before unbounded reads/copies/parsing. No shell execution, environment/secret collection, test execution, network/database/provider/browser or whole-tree discovery is needed to snapshot/freeze/verify.
- **C6 — Caller-pinned readonly verification.** Verify requires a caller-provided expected inventory SHA256 and checks exact inventory bytes against it before trusting parsed rows. Refuse missing/malformed expected SHA and inventory replacement even if replacement rows self-consistently match changed files. Recheck schema/ownership/allowlist/contained nonredirected paths, all source/base/dependency/evidence/contract/output digests and bounds; changed, missing, escaped, redirected or duplicated inputs fail closed with a bounded useful report and non-success result. Successful verification is a compact pin-integrity result, never a feature PASS. Verify writes no source, inventory, manifest, contract, verdict, ledger or success marker; any report persistence is an explicit separate caller-owned cache action.
- **C7 — Authority and truthful results.** Helper and CLI expose snapshot/freeze/verify integrity operations only. They cannot close manifests, synthesize checker verdicts, rewrite ground truth, change skills/enforcement or automate acceptance of negative-runtime helpers. Results distinguish complete integrity from refusal/incomplete and include measured capture/freeze/verify timing rather than invented savings. Feature acceptance still requires independent scoped semantic review, meaningful affected/downstream tests and a matching checker verdict. Full T057/nine-area/live/hosted-CI acceptance remains separate and HOLD.
- **C8 — Meaningful isolated behavior and actual compatibility.** Existing focused Node tests plus an independent boundary probe exercise real filesystem bytes in private contained cache fixtures, including a realistic three-source CRLF/BOM and absent-new-file scenario, drift during capture/freeze, concurrent/no-overwrite attempts, symlink/junction/escape/credential/duplicate refusals, modified/missing base/final/contract/dependency/evidence/receipt/output pins, malformed/bounded inputs and replaced inventory with caller digest unchanged. Include positive CI `sources` and B7/D3 `entries` compatibility against actual current pinned inventories or explicitly attributed preserved copies, not invented title-only adapters; originals remain untouched. No mutation of production files is authorized. Tests are timeout-bounded, one worker, UTF8 output; required contracts verifier runs with vacuity disclosed. No broad suite.
- **C9 — Frozen handshake and measured independent review.** Complete `checker-packet-snapshot` ready-for-check manifest/packet names cycle, exact two new-source final/base-existence pins, dependency map, contract pin, command/output receipts and C1–C9 coverage. Recheck pinned candidate/dependency/evidence bytes before independent commands and immediately before verdict. Changed bytes/cycle require HOLD/resubmission. Only checker writes the matching verdict; maker closes matching PASS. Record reviewer preparation start/end, maker source/tests completion, contract wait/READY queue and formal actual check phases separately. Missing measurements are UNKNOWN, not inferred by subtraction. The 120–180 second target never excuses omitted required checks or a false duration claim.

No filed issue-fix corpus is claimed. Findings require exact reproductions and are sent to the root's serialized ledger owner. Checker owns only this independent contract, matching verdict and ignored scoped evidence; no maker-source, global tracker, Git, governance or enforcement edits.
