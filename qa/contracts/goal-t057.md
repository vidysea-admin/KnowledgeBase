## Current unit acceptance

- **C1 — Mounted operational navigation.** The real protected App route and main navigation mount `/operations`. It consumes existing authenticated sessions, activity-health and notifications clients, with usable links to existing Sessions/detail, Explorer, Activity & Health, Provider jobs, Notifications, Gaps, Analytics, Status and Setup where the workspace presents those destinations. Root integration owns shared App/Nav hunks. A detached fixture component is insufficient. Existing routes and their accepted behavior remain reachable.
- **C2 — Honest operational session views.** All/attention/processing/ready filters have explicit deterministic definitions grounded in returned transcribe/index statuses. Failed and incomplete rows cannot be represented as ready; unknown or missing statuses remain honestly represented. Counts are labelled as returned session rows or a returned sample, never full coverage or a knowledge-health score. Empty results, no matching rows, unknown statuses and unavailable sources are distinct. No division by zero, invented coverage, freshness or completion; an upload operation marked done does not prove downstream index completion.
- **C3 — Independent panels and producer compatibility.** Each sessions/activity/notifications panel uses the existing producer-compatible client shape and reports its own loading, populated, valid-empty, malformed/failure and relevant permission/unavailable states. One panel failure preserves successfully loaded siblings without relabelling failure as zero/no issues. Activity limit/truncation, notification truncation and unavailable notification sources remain visible. No N+1 session-detail fetch campaign, fetch in render or unbounded request fanout; refresh starts a bounded new snapshot.
- **C4 — Grounded deep links and Explorer replay.** Workspace session links use actual returned raw IDs, encoded once through safe URL construction. Explorer URL state replays the requested session and tab across reload and browser navigation; interactive changes and URL state stay consistent. All four existing tabs and year/month/undated browsing remain functional. Unknown, removed or unavailable requested IDs have an explicit recovery and cannot silently claim a different selected session. Invalid tab/query state fails safely. The selected-session graph provenance and inferred/source distinctions in the existing B8 contract remain mandatory; no transitive or tenant-wide entity substitution.
- **C5 — Saved browser-local views.** Saved views persist only an allowlisted predefined filter code, with fixed display labels and a same-origin read-only operations URL. They are described as browser-local preferences rather than server/tenant saved views. No session/node IDs, labels, organisation data, credentials, tenant identity or source payload is added to this storage. Malformed/unknown/duplicate storage entries and blocked storage do not crash the page or execute an unsafe URL; persistence failure cannot be claimed as durable success. Reopening a preset always loads the current authenticated context's fresh data. Local enum preferences do not establish scheduled digests.
- **C6 — Auth generation and tenant safety.** Request/display identity includes the current `apiKey`, `sessionVersion` and refresh generation. Logout, key rotation, same-key logout/login, unmount and refresh immediately invalidate prior snapshots/errors; obsolete success or failure cannot reintroduce prior-context content. No unauthenticated request or previous authenticated content display. URL/query/storage carries no credentials or client-chosen tenant, and existing shared authenticated client transport is preserved. Render returned labels as text. Existing shared current-login 401 sign-out policy remains valid for an older refresh in that same login; it cannot invalidate a later same-key login. Expanded authorized schedule writes and guarded adapter boundaries are governed by C10–C18 below, rather than the initial read-only workspace scope.
- **C7 — Immediate downstream consumption and focused independent evidence.** Review all new/changed logic and relevant consumers using pinned source and dependency hashes. Focused tests cover definitions/counts, partial failures/malformed producers, saved view fallback, encoded IDs/URL replay/invalid or removed selection, and independent auth-generation races including same-key reauthentication. Verify actual App/Nav integration and Explorer consumer, run the frozen-contract verifier (disclose vacuity), and require a successful affected web typecheck/bundle with exact pinned receipts. Attributed immutable maker evidence may supplement independently reproduced behavioral probes. No full suite, mutation, live DB/provider call or browser runs without the root's appropriate lease/authorization.
- **C8 — Actual independent live UI gate.** Before UI PASS, the checker independently drives the actual mounted application, using authorized nonproduction fixture/sample data without production writes. Prove workspace loading/populated/empty/partial-failure/permission/logged-out/refresh behavior, preset replay and session-to-Explorer/tab/detail navigation. Verify usable mobile/tablet/desktop layouts and accessible control/error labels; observe correctly authenticated read requests and explicitly confirmed authorized local config/run/reconciliation requests without credential URL or tenant override. Actual external send/Sheet write requires separate exact authorization and cannot be inferred from UI controls. Maker screenshots, jsdom, static inspection and an indirect browser report cannot replace this independent evidence. If root/browser/host evidence is unavailable, persist HOLD naming this gate. Do not retroactively recertify all T-057 surfaces using one workspace smoke.
- **C9 — Frozen handshake and truthful verdict.** Maker manifest/packet has `ready-for-check`, exact slug/cycle, complete candidate and integration/dependency hashes, changed-call-site map, producer/sample provenance, clause coverage, exact command receipts and explicit whole-task gates. ## Expanded authorized local integration acceptance

Root resumed and expanded the implementation to actual source-health consumers, durable daily/weekly digests and guarded metadata Sheets integration. These criteria preserve the initial UI/provenance requirements, add full auth/data-write/credential ceremony, and do not grant real account access, production writes, external sends, host activation or browser activity. A manifest still marked building is not a checking candidate.

- **C10 — Source counts and health semantics.** Actual existing GET /sources and GET /watch-state outputs drive separately labelled registry counts, current seen/ingested/failed state counts and server-derived heartbeat staleness. Validate consumed shapes, duplicates and accepted source types; unknown registry kinds are disclosed rather than dropped or invented. No sources/no heartbeat means unavailable knowledge of coverage/liveness, not a healthy system. One reader failure preserves siblings. Source counts, queue activity and registered integrations cannot become an unapproved coverage or knowledge-health score.
- **C11 — Durable tenant-scoped configuration.** Actual API routes and mounted frontend consumers read and save daily/weekly enabled configuration and expose current revision/next run/attempt/result/success. Reads never create state; defaults are disabled. Auth-derived tenant/key identity is the only identity; unknown body/query fields cannot supply a tenant, actor, target, interval or credential bypass. The central canonical schema, generated types and required migration/index/validator integration agree with the collection implementation and actual consumers. Independently exercise the real scoped store through a bounded hermetic driver, restart/reload, malformed/foreign persisted data and production-write refusal; fake state maps alone do not prove store semantics. Production writes remain independently gated.
- **C12 — Authorization and audited transitions.** Existing T-060 current key/account/role/scopes enforcement protects read, manage, run and receipt reconciliation. Viewer/read-only principal cannot save, run or reconcile; revoked/deactivated/foreign/missing-scope identities refuse without state or outbound effects. Recheck authorization under its actual serialized authority immediately around every durable transition and external executor initialization. Do not hold its authority lock while awaiting external IO. Atomic schedule CAS and append-only per-revision audit attribute the auth-derived actor and cannot silently lose history. Audit-capacity refusal happens before an irreversible boundary and never trims prior records.
- **C13 — CAS execution and bounded worker.** Expected revisions, tenant-scoped natural identity and secret lease ownership prevent duplicate concurrent claims/execution and stale completion overwrites. At most one winner sends/writes for a competing claim; stale/malformed revisions refuse. A future/not-enabled/disabled-worker schedule is a side-effect-free no-op or explicit refusal. The one-shot host re-verifies its configured existing service key each invocation, derives identity from that verification, calls the actual service and preserves per-kind outcome visibility. Actual supervisor registration/invocation and due execution must be proven separately before claiming automatic schedules; a passive host factory is an interface, not active scheduling. Bound source/store/transport/worker operations, response sizes and fanout, and propagate deadlines honestly.
- **C14 — Configured target and credential boundary.** Adapters default unavailable and may run only for the exact operator-approved tenant, provider account, recipient or Sheet ID/dedicated tab/range and approval reference. API/UI cannot choose arbitrary targets or reveal/change provider secrets. Changing a target/account/approval binding cannot reuse an old delivery receipt as new proof. Treat ambient CLI identity and token/account configuration as explicit live identity gates; environment strings and local mock receipts alone do not establish Approver authorization or real identity. Process launch avoids shell interpolation/visible windows; external HTTP uses fixed approved origin, bounded read, no unsafe redirects, safe credential handling and sanitized public failures. No secret/lease/raw provider error appears in response, browser storage, query, audit or evidence.
- **C15 — Honest payload and receipt semantics.** Export only a deterministic bounded tenant-owned metadata snapshot with explicit returned/truncated/ready definitions. Refuse duplicate/foreign/malformed/oversize source rows before outbound. Digest uses bounded counts and actual producer-derived notification-source availability/truncation, with no notification titles/details/IDs or transcript/source-location disclosure. Sheets uses the dedicated approved fixed range, RAW literal cells, exact padding/old-row removal and checked readback; formula-like titles cannot execute. Label metadata-only scope consistently; neither export proves a complete semantic knowledge bank. Successful configuration or an HTTP/CLI acknowledgement alone is not delivered/synced success: verify exact Gmail sent-message identity/header/body or exact Sheet content/receipt. Distinguish verified provider submission from recipient inbox receipt; do not imply exactly-once email delivery.
- **C16 — Durable uncertainty and receipt-only recovery.** Persist run intent and ownership before any possible send/write, then bind the actual payload/attempt revision/time and approved target into persisted run identity before outbound. Ambiguous outbound failure, timeout, crash after possible delivery and expired lease disable the schedule as uncertain and cannot automatically resend or be enabled through a config shortcut. Receipt reconciliation is explicitly authorized/confirmed, read-only at the provider and bound to that exact persisted attempt/content/target. Missing, duplicate, malformed, tampered, changed-target or unavailable receipt leaves uncertainty; success records an audited verified outcome and still leaves the schedule disabled until separately enabled. Reconciliation must work without current source-data coincidence and must never silently generate/resend a new payload. Capacity and concurrent/revoked-authority reconciliation behavior remain honest and preserve prior state.
- **C17 — Actual consumers and notification compatibility.** Current server composition mounts the protected router or explicit unavailable route, with tenant-scoped bounded sessions and real notifications collector dependencies. UI reads exact configuration/preview responses and performs real PUT Save plus separately confirmed POST Run/Reconcile through the shared authenticated client, handling revision conflict, refusal, unavailable, failed/running/uncertain/succeeded states distinctly. Same-key sessionVersion/refresh ownership fences mutations as well as reads. Existing notifications UI/client must consume both the accepted three-source response and current optional fourth file-queue producer shape with truthful source availability and safe projection; actual collector output must be consumed in behavioral evidence. Preserve original read-mark behavior without claiming tenant-persisted marks. Actual API/web/scripts/type/bundle consumers are included in final integration pins.
- **C18 — Independent focused proof and remaining live gates.** After frozen READY and root CPU lease, independently reproduce relevant actual auth/router/store/concurrency/recovery/producer/adapter/UI/worker probes; no live DB, account, provider, send or broad suite is authorized by this check. Include negative concurrent claim, audit-capacity, cross-tenant, role-revocation, same-key stale response, unverified/tampered receipt and uncertain reconciliation cases derived from the boundary, not only maker's happy paths. Verify central schema/generated/migration and composition pins and frozen verifier with exact receipts. Hermetic adapter IO injection may establish local boundary behavior, never real delivery, actual supervisor scheduling or independent browser/whole-task proof. Missing required live gates yield HOLD; list each exact absent proof.
