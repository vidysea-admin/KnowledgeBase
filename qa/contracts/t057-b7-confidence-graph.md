# T-057 / B7 — Knowledge Graph confidence filter

Checker-owned standalone criterion contract. The exact catalogue requirement is `.goal/catalogue.json` B7: **Knowledge Graph (graph_edges) with confidence filter**. This unit adds a confidence-filter view over the accepted authenticated graph endpoint; it does not complete parent T-057 or the operational goal. The new threshold seam has no prior PASS. Accepted graph/backend/client/Brain seams remain read-only, including broader graph seams with two or more PASSes.

Grounding: `apps/web/src/api/graph.ts` calls authenticated `GET /graph`. Its accepted producer `packages/index/src/graph/build-graph.ts` unions tree_index and graph_edges into canonical nodes and relationships with source/target/type, origin, inferred, optional edge confidence, sessionRef and evidence. Confidence belongs to the **edge**, not the node. The producer keeps finite numbers without enforcing [0,1]; tree edges have no score, and nonnumeric/nonfinite raw scores can be omitted. Missing confidence cannot establish a measured score. The existing tenant-scoped API can return 404 when no graph exists.

## Criteria

- **C1 — Actual mounted feature.** The actual protected App route and Nav link mount the new confidence graph page at the declared route. It uses the existing loadGraph/auth/client flow, consumes graph_edges relationships, and offers a usable threshold control. A detached demo or fixture-only graph does not satisfy B7. Preserve B8 and other existing routes/navigation; only the maker's new files and root-released minimal App/Nav hunks may change.
- **C2 — Defined edge threshold.** Active filtering retains exactly relationships whose confidence is a finite number in inclusive [0,1] and is greater than or equal to the selected finite inclusive [0,1] threshold. Exercise 0, 1, exact equality and a value immediately below threshold. Missing scores are unknown; strings, null, NaN/infinities and out-of-range values are invalid when actually present. Neither group may be fabricated as 0 or 1 or included as meeting an active threshold. A default unfiltered view may preserve returned relationships, but their unscored/invalid state is explicitly labelled. An invalid threshold must fail safely rather than behave as an unfiltered success.
- **C3 — Honest counts and source semantics.** Clearly distinguish original returned relationships, known-valid/unknown/invalid confidence, threshold-qualified relationships and any displayed capped subset. Denominators and truncation must be defined and consistent; a rendered cap cannot be called the complete graph or full corpus coverage. Preserve returned edge type, origin and inferred flag rather than deriving stated-versus-inferred from a threshold or treating tree structure as scored source evidence. Confidence display does not imply calibrated certainty or recalculate producer facts.
- **C4 — One consistent visible subset.** Apply the threshold before any documented layout cap. Visible node endpoints, SVG edges, selectable nodes, neighbors and evidence are derived from the same final displayed edge subset. Excluded low-confidence/unknown/invalid edges cannot survive in a detail panel or evidence list after filtering; hidden capped edges cannot be represented as visible relationships.
