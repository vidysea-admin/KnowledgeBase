# Contract: unknown cancelled Calendar events (tombstones) (checker-authored 2026-10-11, cycle 0 of calendar-unknown-tombstone-non-interference)

Ground truth for any unit touching `unknown-tombstone` in `reconcileWebinarSources`. Both hazards must hold:

1. NON-INTERFERENCE (ISS-T036CAL-011): an unknown cancelled event (id not on record, e.g. an outsider's send-then-cancel invite) must never alter a trusted Calendar row, a linked Gmail+Calendar pair, or `newStartsBlocked`, in either scope and either every-webinar mode. Property: outcomes identical with and without arbitrary tombstones, including ones copying a trusted row's start, title, organiser or link.
2. NO JOIN OF A CANCELLED MEETING (ISS-WEBINARRELEASE-013, D-060 floor "unknown tombstone empty effective feeds/gate"): a meeting cancelled before the client ever stored its Calendar event, whose Gmail invite is still present, must not be scheduled. Any narrowing must keep this for every tombstone shape Google can return (id only; id + start; recurring instance with originalStartTime only; all-day; id + start + link). A selector keyed on equality of the tombstone's start with a Gmail row's start is NOT sufficient: Gmail starts are scraped from mail text and an unknown timezone is read as IST (apps/api gws-gmail.ts), so a +1 minute or tz-shifted start escapes it.
3. Known cancellation (id on record) always unschedules the meeting and its linked Gmail copy, whatever unknown tombstones surround it.
4. Boundedness: a hold caused by an unknown tombstone must expire or be releasable. A stored tombstone must not hold rows forever, and a fresh or reset state (baseline fetch, no time filter) must not leave email-only meetings permanently unjoinable.
5. Tests: a near-miss test (tombstone start +1 min and tz-shifted vs the Gmail copy's start) and a differently-formed-link test must exist and fail on an approximate or identity-only selector; the id-only case must be pinned by a D-060 test.

State at cycle 0 (2a19974): 1 and 3 hold (8,000 runs, 0 violations; 1,000 known-cancel runs, 0). 2 FAILS for start-only and trusted-identity tombstones (ISS-TOMBSTONE-002/003). 4 FAILS (ISS-TOMBSTONE-004). Residual by design: id-only holds all unlinked Gmail rows, with no expiry.
