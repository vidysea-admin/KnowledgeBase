## Facts the criteria rest on
- Stanza: `<notification type='companion_reg_refresh' from id t>` with one child `<companion_reg_refresh/>`; a second child name `pair-device-rotate-qr` is accepted the same way (seen as accepted by three implementations, not observed on the wire). It arrives after the phone scans the QR.
- Required handling: the usual notification ack goes out (`<ack id=<same id> to=<from> class=notification type=companion_reg_refresh/>`). If the notification has either child AND `creds.me` is unset: `creds.advSecretKey` becomes 32 fresh random bytes (base64), `creds.update` is emitted with it, and the SAME QR ref is rendered again with the new secret (the ref index does not advance, the QR timer is untouched). If `creds.me` is set the secret is left alone. The pre-login ack guard reads `creds.me?.id` so an unpaired session does not throw.
- The patch touches `lib/Socket/socket.js` and `lib/Socket/messages-recv.js` only, about +45 -8 lines, no new file under `node_modules`. The pin stays `7.0.0-rc14`. D-024 amends D-023 item 4: D-023's "only adds lines" and "socket.js only" no longer hold, the stanza and reply are confirmed upstream, the patch is the backport of PR 2765 and is dropped when upstream releases the fix.
- Mechanism (decision 3): `patch-package`, exact-pinned dev dependency, patch file `patches/baileys+7.0.0-rc14.patch`, run as the explicit step `npm run patch:baileys` (= `patch-package --error-on-fail`, plus whatever flag C2-C4 needs). No `postinstall` hook.

## Invariants (what must not change)
- **[C2-I1]** `baileys` stays exact-pinned `7.0.0-rc14`; the only added dependency is the one exact-pinned `patch-package` dev dependency (and its lockfile entries); no other version changes.
- **[C2-I2]** No `postinstall`, `preinstall` or `prepare` script is added; the apply step is only the explicit `patch:baileys` script (and the Dockerfile line that runs it).
- **[C2-I3]** `git diff --name-only HEAD` is a subset of the C2 file list; no change under `.claude/`, `contracts/` or `scripts/append_decision.ps1`.
- **[C2-I4]** [SECURITY CLASS: credential handling (checker-tagged; the maker's stop rule already treats it so)] The patch writes only `creds.advSecretKey`, and only when `creds.me` is unset: in every test the creds object before and after is deep-equal except that one field, and a registered (paired) session is never altered.
- **[C2-I5]** `src/wa/readOnlySocket.ts` `ALLOWED` is unchanged; no secret, real phone number, JID, ref or QR payload in the fixture, any log line or test output (the QR strings the test builds use synthetic keys).
- **[C2-I6]** No network and no real WhatsApp connection in any test (fake `ws` and fake timers only).

## Out of scope / ignore
Not in this unit: the live pairing (plan row 11); the Dockerfile (C3C); any change to `readOnlySocket.ts`; moving the pin or taking the unmerged fork; handling any other notification type.

## Stop rule
Stop rule: a finding outside these criteria is filed and not built; a finding that the patch can alter a paired session's credentials is credential handling (security class) and is never capped.
