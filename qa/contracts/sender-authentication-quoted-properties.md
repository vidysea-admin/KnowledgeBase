## Problem and authorized behavior

Actual retained receiving-Gmail grammar for a historical Zoom confirmation contains a quoted `smtp.mailfrom` property, alongside exact `dmarc=pass header.from=zoom.us`. The old canonical parser rejects every quotation mark. The repair supports a narrow well-formed quoted-property atom representation while preserving who may assert authentication and which identity may be trusted. Sanitized source grammar is a real-source observation, not a live post-change measurement or current registration proof.

[RFC 8601 §2.2](https://www.rfc-editor.org/rfc/rfc8601.html#section-2.2) defines property values separately from method/result and refers to MIME value/quoted-string syntax. This unit deliberately supports a narrow safe subset of observed property quoting; it does not claim complete RFC grammar support or treat quoted text as authentication authority. Existing strict EMAIL-argument parsing in `qa/contracts/iss-capture-001-trusted-sender-domain-spoof.md` C3 is unchanged. `contracts/contracts.json` currently has empty stages; verifier success must disclose that vacuity.
