## Remaining acceptance criteria

1. **Official library and thin wiring.** The executed pipeline and remaining Ask library substitution use the official exactly pinned JS LangGraph 1.x dependency as authorized by D-161. Independent evidence must show actual compile/invoke/node routing on the selected path, not just an import, installation or diagnostic trace. Nodes call existing stage functions; there is no second business-policy or checkpoint authority.
2. **Actual entry point and consumption.** The intended authorized entry point submits durable jobs and drives the capture-to-index sequence, including fresh captures and recovery of existing recorded artifacts. A recorded sample traverses actual media/transcript/extraction/index functions. Each required stage consumes the preceding artifact; the final tenant/session/generation/input proof is validated by the existing completion consumer. Then the existing retrieval/Ask consumer successfully consumes that indexed sample with resolving provenance. Fake children, a nonempty filename or an index marker alone cannot establish this criterion.
3. **Durable resume.** A bounded process termination/restart probe uses real temporary queue/run-state files. It demonstrates acknowledged stage checkpoints surviving a new process, correct resumption of pending work, no re-execution of already committed compatible stages within the same generation, and truthful incomplete state before the final proof. Changed input invalidates incompatible progress. Crash after an external side effect but before acknowledgement is explicitly at-least-once; replay must preserve valid output and avoid duplicate or foreign writes. No power-loss durability claim is required or allowed without separate proof.
4. **Leases and long stages.** A controlled handler outlasting the configured lease shows actual queue/stage heartbeats prevent concurrent ownership, stop on settlement/error, and do not allow a superseded holder to commit. Expiry/reclaim and a restarted worker maintain fresh attempt identity and lease fencing. Real long provider/media stages need operational evidence before claiming the live pipeline gate met; a timer implementation or short fake-stage success alone does not prove it.
5. **Failures, retries and disposition.** Actual child/provider failure classifications reach the established retry policy. Retryable failures preserve compatible committed progress and retry within the policy; exhaustion/nonretryable failure becomes a visibly failed/dead job, never success (D-139). Same runKey resubmission creates a new attempt/generation under that policy. Downstream stages do not run after their required predecessor fails, persistence errors cannot be acknowledged as success, and recovery/status consumers expose failure and successful recovery truthfully.
6. **Tenant and write boundaries.** Every submission, claim, heartbeat, completion, failure, checkpoint and downstream write carries the validated tenant and the matching run/session/generation. Missing/malformed/foreign tenants, forged or stale leases and mismatched artifacts/proofs refuse without modifying owned state or leaking foreign payloads. Files remain confined to the configured roots; corrupt state is preserved. Use real on-disk probes for the affected write boundary, alongside focused contract tests. Live DB writes require the explicitly asserted `lkb_staging` target under D-143; production `lkb` is never written. Existing uncapped security/data-write reproductions remain the floor.
7. **Ask equivalence and activation scope.** The official Ask graph retains D-142's retrieve → evaluate → refine → answer structure and preserves established results, citations, refusals, error behavior, provider calls and tenant-scoped audit writes against the independently sourced pre-substitution baseline. Required failure/poisoned-candidate/bounded-budget cases and relevant original ledger reproductions pass. Verify actual API caller consumption. The official executor remains unexported and off by default under D-142; an explicit opt-in may preserve the existing shared-node production path while proving library consumption. The current shared-node delegation is not proof of official execution. A proposal to activate the official executor by default requires an explicit Umesh decision; this contract does not authorize activation or silently reinterpret D-142.
8. **Operational compatibility.** `LKB_PIPELINE_GRAPH=1` selects the pipeline graph; unset/other values preserve the existing off-path behavior and create no graph state. Required completion/status consumers and the approved 30-day terminal-job retention policy (D-128) remain correct, without pruning active jobs or concealing failures. Document remaining host/live/user gates expressly; deployment, supervisor activation and production promotion require their existing authorization.
