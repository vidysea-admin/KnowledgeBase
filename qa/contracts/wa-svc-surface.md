## Criteria
- **[C3A-C1]** Token. (a) For each of the six routes, one unknown path under `/svc/v1` and one wrong method: no `Authorization`; `Basic <x>`; `Bearer` with an empty token; a wrong token; a token one character off; a token of 1 and of 4096 bytes; the right token under a `Token` scheme; the right token in a query string or an `X-Api-Key` header: all return `401` with the same status, the same body bytes `{"error":{"code":"unauthorized","requestId":"..."}}` and the same header set (apart from `X-Request-Id` and `Date`), no `WWW-Authenticate` detail, and the fake store's call counter stays 0. The token check runs before routing, so an unknown path or wrong method without a token is 401, not 404 or 405. Health is not exempt. (b) The right token succeeds on every route; with `SERVICE_API_TOKEN_NEXT` set, the second token also succeeds; with it unset or empty, `Authorization: Bearer ` (empty token) and the string `undefined` are 401 (an empty second token must never match an empty credential). (c) The comparison is SHA-256 digests of both sides through `crypto.timingSafeEqual`: `grep` shows `timingSafeEqual` over two 32-byte digests in `src/api/svc.ts` and no `===`, `==`, `startsWith`, `includes` or `localeCompare` on the supplied token. Timing is not measured (a timing measurement on a laptop is noise); this is a code check and says so. (checker-tightened: the grep is a screen only; the checker also reads the compare function, and a helper that wraps the supplied token and compares it indirectly fails (c) the same way.) (d) Failed-authentication limit (D-025 item 2; contract AC-A7 and section 8): ONE process-wide counter of failed authentications, not one per source address. On a fake clock the 21st failure inside 60 s gets `429` with code `rate_limited`, a `Retry-After` header and `retryAfterSec`, with the same body shape for every failure kind; the counter resets after the window; failures sent from different remote addresses (a stub if only one loopback address exists) share the one counter; a request carrying a valid token is never refused by this limit, including while it is tripped (200 on every route). This unit does not claim the contract's per-source-address test (`archiver-service-api.md:423` and `:472` say "per source address"; D-025 item 2 records that Cloud Run gives no usable source address). (e) The token never appears: with a canary token and canary wrong tokens, the captured pino output at debug level (success, each failure kind, 429), every response body and every response header contain neither the configured tokens nor the supplied `Authorization` value.
  Check: `npx tsx --test src/api/svc.test.ts`; the `grep` in (c) as a checker command.
- **[C3A-C2]** Envelope and request hygiene. (a) Every response the process sends, on any path and any status (200, 400, 401, 404, 405, 409, 413, 415, 429, 500, 503), carries `X-Archiver-Api-Version: 1` (client `:110` fails the call as `version_mismatch` otherwise) and `X-Request-Id`; no response is a 3xx (client `:109`), including for a trailing slash or a double slash; every 200 has `Content-Type: application/json` (client `:116`).
