# T-054 full parent acceptance — transcript review and speaker mapping UI

Owner: independent checker. Priority tier: 3, roadmap parent feature; tenancy and data writes require full maker-checker ceremony.

Sources: TASKS.md T-054 and its 2026-10-14 scope note; .goal/goal.json T-054; .goal/catalogue.json A3 (`/transcript-review`); qa/contracts/t054-transcript-review-planner-editor.md; qa/manifests/t054-persist.md. The attached 40-task implementation brief explicitly requires whole-feature acceptance and immediate downstream proof. The existing planner/editor and persistence scoped PASSes are foundations, not acceptance of this parent.

## Required behavior

1. **Reachable product.** The authenticated production web application exposes `/transcript-review` and a practical session-selection/navigation path. The selected transcript editor uses the real mounted API routes, configured persistence and configured refresh executor. A standalone component, test-only Express app, simulated HTTP receipt or unavailable production dependency does not satisfy this clause.
2. **Precise text corrections.** Review loads the effective canonical transcript and its revision. Corrections name existing turn IDs, preserve their IDs/timing/provenance and leave unrelated turns unchanged. Reject empty/no-op reviews, duplicate/foreign IDs, malformed or over-limit payloads and blank/over-limit reasons. The original source turns remain available and unmodified.
3. **Precise speaker mapping.** A mapping applies only to explicitly selected consecutive passages with one current speaker reference and within the accepted 100-turn bound. Reject disjoint, mixed-speaker and foreign selections. The same positional speaker label elsewhere remains unchanged. A correction may change text and the selected speaker block in one revision.
4. **Authenticated isolation.** Production read, commit, history and refresh routes require verified authentication and the appropriate scope. Tenant/session/actor/time provenance is trusted server context; body/query smuggling cannot override it. The same session ID may be independently reviewed in two tenants without head/history collision. Cross-tenant reads, history, writes and refreshes reveal or alter no foreign content. Audit accurately describes the principal identity actually available; do not claim individual human attribution from a tenant-only identifier.
5. **Durable conflict-safe commit.** Schema-first persistence and applied required indexes enforce one head per tenant/session. A loaded revision and matching strong precondition guard every write; concurrent first/subsequent commits have at most one winner. A committed receipt follows durable persistence of effective changes, audit facts and revision-bound refresh intent. Conflicts, storage failure and uncertain delivery retain the distinction between a confirmed commit and an unconfirmed save. No partial accepted edit or lost unrelated correction.
6. **Accessible immutable audit.** Each accepted change retains trusted actor, time, reason, parent/new revisions and detached before/after values for every changed turn. History is append-only, tenant-bound and accessible in the product. If secondary history persistence fails after the durable head commit, the current committed audit must remain accessible or be recovered on history read/recovery without needing another human correction. Restart must preserve revision and audit truth.
7. **Review survival and canonical consumption.** Normal session transcript and citation/evidence readers consume effective reviewed text and identity. Reindex preserves corrections and existing reviewed knowledge according to its standing preservation rules. A re-ingest that removes/renumbers reviewed turn IDs must surface a reconciliation/conflict state; silently dropping the review while presenting successful/current knowledge is unacceptable. Immutable source text is not substituted for the reviewed transcript during downstream derivation.
8. **Actual downstream refresh.** The configured executor re-derives the affected claims, session page, chunks, tree and graph consumers from the reviewed revision using the existing real stages. A plan, callback count, injected no-op or bookkeeping-only update is not refresh completion. Required stage failures/degraded output leave refresh pending/failed with an actionable retry; `complete` requires actual successful downstream consumption. Existing human-reviewed claims must not be silently erased by this path.
9. **Publication fence and recovery.** Superseding commits prevent an older refresh from replacing newer derived data or claiming completion for the newer revision. Fence actual downstream writes/publication as well as refresh-status writes. Exercise supersession during execution, executor failure, retry and restart/recovery. If the configured datastore lacks required atomicity/transaction capability, fail closed and report the committed correction and unresolved refresh honestly.
10. **Mounted review UX.** The real client/editor supports load, passage correction, bounded speaker-block selection, reason, save, canonical reload, audit/history and refresh status/retry. Save is enabled only for valid changed content. A durable receipt triggers canonical revision verification before another edit. Conflict or uncertain save retains drafts and prevents unsafe retry until reload. Pending/failed refresh visibly warns that dependent knowledge may be stale. Callback/reload failure cannot reclassify a confirmed commit as an uncertain write.
11. **Identity/lifecycle safety.** Changing API identity/session or leaving the page immediately hides previous identity content and invalidates stale asynchronous work. Late loads/saves/history/refresh responses cannot alter the current transcript, notices, callbacks or controls. Render transcript, speaker, reason and history data as text; no executable markup.
12. **Whole-feature evidence.** Supply a ready-for-check manifest and packet with matching cycle, exact changed-file/dependency map, final hashes and exact commands/results. Independently verify the mounted behavior, real persistence/index semantics, sample affected stage and immediate downstream consumption; retain the required `contracts/verify_contracts.py` result. Relevant schema/generated-type/migration and targeted build checks must pass or have attributable existing limitations that do not invalidate the feature. Root CPU/browser leases govern execution; missing leases/evidence mean HOLD, not an inferred PASS.

## Acceptance evidence matrix

| Boundary | Required proof |
|---|---|
| Real app composition | Production API/web mounts and dependencies; authenticated `/transcript-review` navigation and real client requests |
| Correction and mapping | Retained sample turns; text plus one block changed; repeated labels, timing, originals and unrelated turns preserved |
| Writes and security | Invalid/auth/scope/tenant-smuggling cases; two tenants sharing session ID; first/subsequent race; durable restart and audit recovery |
| Downstream integration | Reviewed transcript reaches normal reader and actual claims/page/chunks/tree/graph derivation; reviewed knowledge survives reindex |
| Publication and recovery | Supersede during refresh cannot publish stale output; failure/retry/restart; incapable storage fails closed |
| UI lifecycle | Mounted save/reload/history/refresh/conflict behavior; old-identity late-response fencing; text rendering |
| Repo definition of done | Frozen validator plus exact sample-stage and immediate-downstream command/output on checked final bytes |

Only an independent checker may PASS this parent after all clauses have evidence. Scoped unit PASSes may be reused with attribution for unchanged checked bytes; they never substitute for the missing product, persistence, publication or downstream gates. Record remaining unmet clauses explicitly in HOLD/FAIL and keep T-054 in_progress.
