## Bounded implementation acceptance

A matching unchanged goal-t055 maker packet may receive **scoped code PASS** only when every applicable C criterion below is demonstrated across the actual producer, persistence/read API and immediate UI consumers. The manifest must identify its exact authorized source scope, cycle, changed call sites and dependency pins. Missing or unwired listed functionality is HOLD or FAIL, not a complete T-055 implementation. Shared schema, generated types, migrations, server, composition, App/Nav and trackers are written only by the central integrator; checker never modifies product code.

- **C1 — Real document page provenance.** Preserve page boundaries supplied by a real page-aware reader or a separately identified page source; every accepted highlight/evidence item names its tenant-owned source/version, actual positive integer page, and exact nonempty quote occurring on that page. Do not infer PDF/DOCX pages from paragraph order, character offsets or transcript seconds. Empty/invalid pages, mismatched source/version, absent quote and forged page references are rejected or explicitly unavailable. Stable natural identifiers and idempotent repeat ingestion preserve page attribution. Existing plain-text T-020 output remains distinguishable as character offsets without page evidence. Supported formats and genuinely unavailable page numbering are explicit; tests must exercise the actual page-preserving producer rather than a hand-authored final DTO alone.
- **C2 — Persisted document highlights and citation consumption.** The page-aware producer's accepted output passes canonical schema validation, persists through an actual tenant-scoped storage boundary, is read by the actual authenticated API route, and renders in the mounted UI with source title, page number, quote and an actionable source/page target. A page link must identify the exact cited source and page; a transcript turn link cannot substitute for a page citation. Claims/highlights lacking valid evidence are withheld with explicit counts or fail honestly. Unknown/deleted/version-changed sources or pages never attach to a different document. A real sample document fixture is consumed end to end offline; a mock database is acceptable only when it enforces recorded filters and the concrete storage adapter predicates are reviewed.
- **C3 — Useful topic profiles.** Actual produced topic identifiers and tenant-namespaced claim references match without accidental prefix/substring collision. Profiles show relevant claims with valid evidence, linked sessions/documents, and visibly distinguish stated/inferred relationships, origin, recorded confidence and quality/status. Unavailable or untrusted taxonomy remains explicitly unclassified. Label keyword lenses may remain useful derived filters but cannot claim verified category or extraction quality. Unknown/conflicting ownership refuses citation links; producer-compatible positive/negative cases and immediate evidence consumers are exercised.
- **C4 — Trustworthy speaker profiles.** Profile identity uses stable person/alias identifiers and source evidence; raw diarized labels, suggested names and human-confirmed names remain distinct. A suggested display label never becomes confirmed identity or an asserted counsellor. Organization/role fields appear as asserted only with their own accepted provenance; absent fields remain unavailable. Segment/block speaker attribution must not bleed into unrelated same-label blocks or sessions. Existing D-132/D-141 policy remains authoritative: model suggestions stay suggestions pending human confirmation. Show accepted source quote and session/turn citation, with honest unresolved state; evidence from another tenant cannot establish identity.
- **C5 — Saved curated collections.** Create/read/update/delete and membership changes use durable tenant-scoped storage, verified auth-derived tenancy, schema-shaped data and stable IDs. A saved collection survives reload via the actual read route. All referenced sessions/documents/entities are authorized for the caller; foreign, missing and malformed members fail closed without partial hidden success. Duplicate/repeat writes have defined idempotent behavior and membership deduplication. Derived month/theme views remain clearly distinct from saved collections. A stub, local in-memory UI array or a no-request unavailable response does not satisfy saved collections. Collection selection and member links consume saved server data; bounds and empty/error states are explicit.
- **C6 — Safe resource and program directory.** Show recorded resource/source metadata and provenance, useful filters, explicit unknown classifications and supported directory entries. No invented programs, institution roles, endorsements, ingestion completeness or quality scores. Public links accept safe absolute http(s) only, rejecting controls, surrounding whitespace, credentials and unsafe protocols; new-tab links use noopener noreferrer. No local source.path leakage. Program semantics appear only when supported by accepted data; raw resources alone cannot be labelled a complete verified program directory.
- **C7 — Auth, tenancy and write boundaries.** Every storage predicate for reads/writes, membership validation and referenced evidence includes the authenticated tenant, including identical natural IDs in two tenants. Request body/query/header tenant values cannot replace verified tenant context. Check unauthorized, revoked/rotated key, wrong scope, foreign identifier, mixed-tenant memberships and deliberate forged evidence cases. No secrets enter links, logs or client data. UI logout/key rotation/refresh/unmount fence prior content, errors and late responses; unauthenticated mounts make no request. All consumed DTOs validate enough structure to avoid treating malformed responses as successful empty data. No provider/network/prod writes are needed for this code check.
- **C8 — Actual mounting, usable states and downstream proof.** Actual protected App/Nav mount and authenticated client wiring are exercised through focused integration, as are source-page citation targets, topic/speaker links and saved collection member consumers. Loading/empty/missing selection/not found/403/error states remain useful; graph or optional capability absence cannot suppress unrelated document/resource results. Truncation and failed quote lookups are labelled accurately. Text renders safely; source strings cannot become executable markup. Evidence covers narrow and wide layouts at source/UI-test scope; no browser is authorized in this check, so required live visual/browser acceptance is a remaining parent gate.
- **C9 — Verification and immutable candidate.** Record manifest slug/Fix cycle, contract SHA256, every affected final file and critical shared dependency hash before and after checks. Independently review complete new/changed logic, concrete storage predicates and consumers; perform at least one independent adversarial behavioral probe outside maker assertions. Run the smallest relevant tests covering C1–C8 and actual immediate downstream consumption, canonical schema validation/generated drift checks if changed, required contracts/verify_contracts.py (disclose vacuity), and final relevant semantic typecheck/build attribution pinned to the same bytes. Exact commands, UTC times/durations, exits, counts and output artifacts are recorded. Issue-fix units replay their own union-ledger recorded reproductions verbatim and report per-ID counts. Changed candidate/cycle after verification requires HOLD and resubmission. No full suite, browser, network/provider, production/export or mutation run is authorized by this contract; focused execution waits for root CPU lease.
