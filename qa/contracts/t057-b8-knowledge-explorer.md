# T-057 / B8 — Knowledge Explorer

Checker-owned criterion contract. Scope is catalogue B8 only: `.goal/catalogue.json` names the year → month → session tree and explicitly identifies missing Overview / Topics / Speakers / Orgs tabs. This does not complete parent T-057, its other product areas, or the operational goal.

Grounding: `GET /sessions` returns `{ sessions }` from the authenticated tenant's scoped session collection; session `date` is a recorded date field, not a title-derived date. `GET /graph` returns the accepted `buildKnowledgeGraph` union: canonical node IDs, session-node `ref`, endpoint IDs, edge `type`, `origin`, `inferred`, optional `sessionRef`, and evidence with optional `sessionId`. A tenant lacking both tree and graph edges receives graph 404. Accepted clients/auth/backend implementations remain read-only in this unit.

## Criteria

- **C1 — Live integration.** The actual web App router and navigation mount the new Explorer page. It calls the existing authenticated sessions and graph clients; fixture-only rendering, a disconnected component, or a route that never consumes the new page is insufficient.
- **C2 — Complete calendar navigation.** All accepted dated session rows remain reachable through deterministic year → month → session groups, across multiple years/months. Selecting a real session changes the selected-session content. Date grouping uses the recorded valid date. Missing/invalid dates have an explicit undated path; a date-shaped title or ID never supplies the missing date. No fabricated session, year/month membership, or silent omission of an accepted session.
- **C3 — Four useful tabs.** Overview, Topics, Speakers and Orgs are selectable for the selected session. Overview identifies its actual session/date/status and provides a correctly encoded link to the existing session detail route. Each entity tab displays the correct returned graph-node kind and usable node reference/link when present, with an explicit empty state when no grounded association exists.
- **C4 — Selected-session provenance.** Topics, people and orgs must have a real graph association with the selected session: a direct session-node edge whose node maps to that session and carries no conflicting explicit owning scope; an edge explicitly scoped by `sessionRef`; or matching per-evidence `sessionId`. A tenant-wide node list, shared/transitive neighbor expansion, label/slug similarity, or another session's direct edge is not evidence for the selection. Conflicting explicit session ownership must not be overridden by an incident selected-session node. Preserve edge origin and inferred-versus-stated distinction in the displayed evidence; do not turn graph derivation into literal speech.
- **C5 — Actual producer compatibility.** Consume the real accepted endpoint shape, including graph_edges and tree_index origins, canonical IDs/raw session refs, edge.type, explicit sessionRef and inherited/matching evidence.sessionId. Behavioral evidence must include output of the actual existing graph producer or an independently checked exact producer-derived payload; convenient client mocks with an invented association shape do not establish this criterion. Source inspection checks the unchanged tenant-scoped producer rather than recertifying it.
- **C6 — Honest absent/error states.** Loading, no sessions, undated sessions, graph-404/not-yet-built, session fetch failure, graph non-404 failure and malformed consumed shape are distinct and usable. Graph 404 may preserve the sessions tree with an explanatory graph absence; other failures must not be represented as a successful empty entity result. No success/coverage claim inferred from empty or unavailable data.
- **C7 — Selection lifecycle.** Switching sessions updates all tab content without carrying the previous session's entities into the new selection. Reloads/auth changes do not keep a no-longer-present selected ID as valid data; empty/removed selections have truthful recovery. Out-of-order promises cannot restore an obsolete response after a newer selection/auth generation or unmount.
- **C8 — Auth and tenant boundary.** Use the existing auth/client flow and its current key; no new query-string credential or bypass. An unauthenticated page cannot request or display previously authenticated Explorer content. Key rotation, logout or a late old-key response cannot retain/reintroduce another authenticated context's sessions/entities/errors. Links safely encode raw session/node IDs; returned labels are rendered as text, not executable markup. No data-write route is introduced.
- **C9 — Verification and immediate consumer.** Focused model/page/integration checks must exercise calendar/undated paths, all tabs, positive and negative provenance, stale selections/promises and auth/error cases. The actual App/Nav integration must be consumed by a successful web typecheck and bundle (attributed immutable maker evidence may be reused with command/exit/output/pins), and `contracts/verify_contracts.py` must run. Browser/DB/provider calls and full suites are outside this check. A vacuous frozen-contract verifier is disclosed, never used as feature acceptance.
- **C10 — Frozen scope and limits.** Review the maker's exact eight-file candidate, manifest slug and Fix cycle, source hashes and changed dependency map. Check final pins before verdict. No mutation of existing graph/sessions/auth/Brain/AppShell/backend code, source corpus/gold, protected governance, global task/goal or other-owner files is part of this unit. PASS certifies this complete B8 unit only; visual/live-server operation, other T-057 areas, received Meet media/index/Ask and locked-RDP/global completion remain separately unproved.
