## Criteria (library, each machine-checkable)
1. **Subset property.** For every input, `out.toSchedule` is a subsequence (same objects, same order, no additions, no duplicates) of `in.toSchedule`; `out.skipped` = `in.skipped` (same objects) followed by exactly one entry per removed item; every removed item carries a string `reason` and a `detail`. Property test with a seeded generator, >= 20,000 cases, malformed rules/state and a misbehaving evaluator included.
2. **Never throws, never mutates** its inputs (deep-frozen inputs, JSON snapshot unchanged).
3. **Identity.** `rules === undefined` returns the SAME selection reference. A valid empty rule set and a valid empty state keep everything (same reference when nothing is removed). `null`, `{}`, `[]`, a string, an unknown version, or a malformed state is treated as malformed (skip, never join).
4. **Veto-only decision table** (engine pair -> action). REMOVE: `skip/meeting-opt-out`, `skip/deny-rule`, `skip/cancelled` (unreachable here), `skip/no-meeting-url` (reachable only for a whitespace-only URL), `needs-approval/invalid-rule-set`, evaluator throw/undefined. KEEP: `needs-approval/no-matching-rule`, `needs-approval/sender-unverifiable`, `join/allow-rule|approved-sender|approved-domain`, and any non-skip result (including garbage/Promise): the default is KEEP. Nothing a rule says can add or resurrect a join.
5. **Does not decide ISS-376.** An event with no explicit refusal (no match, unverifiable sender, allow, approval) is returned exactly as today.
6. **Single matcher.** Opt-out matching is done only by `evaluateJoinRules`; the unit calls it with `sourceId` and with `sessionKey` as the event id and removes if either refuses.
7. **No existing file edited**; tests + `auto-join.test.ts` + `join-rules.test.ts` pass; `tsc --noEmit` clean; `lint-dirsize` OK.

## optedOutMeetings (added by the checker of t037-optout-meeting-identity-store)
- **O1** Optional field, absent in old documents. Loading never adds it and never rewrites a file; an id-only opt-out leaves it absent. A document WITH it read by a pre-unit build is rejected (`unknown field`): loads throw `invalid`, every store mutation is refused, the evaluator returns `invalid-rule-set` (nothing joins). Only the explicit `overwriteInvalid: true` repair path can drop it; no production caller uses that path. Rollback therefore needs the new build or removing the field by hand.
- **O2** Entries are exact strings `url:<platform>:<id>` (from `meetingIdentity`) or `key:<sessionKey trimmed>`; at most 500 entries of at most 200 chars, no whitespace/control chars, deduplicated; any malformed entry makes the whole state invalid (fail closed). Matching is exact string equality only: no prefix, wildcard, case-folding or cross-tag matching (`key:X` never matches a URL identity, `url:X` never matches an event id).
- **O3** Hints are untrusted. A hint that yields no identity (bare host, non-meeting URL, unsupported scheme or host, over-long, degenerate) is ignored: the id is still stored, the response is 200, and the caller must read `state.optedOutMeetings` to see whether anything was stored. The cap (500) is silent in the same way. Over-blocking is bounded to the caller own tenant (file per tenant, tenant from the auth key only), to exact identities, to 500 entries, and needs the `join-rules` write scope; the same tenant can already deny any URL via PUT rules. Tenant A entries never affect tenant B.
- **O4** Only POST /opt-outs reads the hints; `meetingUrl`/`sessionKey` on approvals or PUT is 400. The response echoes the derived entries, never the raw hint.
- **O5** The matcher can only produce a skip, runs on the raw state before validation, never throws, never mutates; hand-written degenerate entries are rejected at load and cannot match.
- **O6** `siblingIds` no longer groups records on an empty or whitespace-only sessionKey; this only removes over-removal (checker: 2000 seeded cases, new kept-set is a superset of old, zero cases where new removed something old kept).
