# Contract — t050-run-state-store (T-050 slice 2, file-backed RunState store)

> Ground truth for `packages/core/src/run-state-store/`. Written by the checker; the maker never edits it. Data-write class, never round-capped. Scope: unwired; single machine; local filesystem; in-process and same-host multi-process concurrency; durability across power loss unverified.

## Security property
An acknowledged `save` is never lost or silently replaced, a reader never sees a partial or zero-length state file, nothing is written, read or deleted outside the configured root, and a corrupt or unrecognised state file is never overwritten or deleted by the store.

## Criteria
1. **Atomicity.** Every write is: exclusive-create temp file in the SAME directory as the target, write, fsync the file, close, rename over the target. A reader loop in another thread over 200 overwrites of 200 kB states sees only complete valid documents (never empty, truncated or absent). On any failure (write, rename) no temp file and no lock is left and the old file is byte-identical. The target is never unlinked before the rename.
2. **CAS.** `save(runId, expected, next)` succeeds only if the stored state's canonical revision equals the revision of `expected` (`null` = the file must not exist). The revision is key-order independent. A state obtained from `load` always succeeds as `expected` when nobody else wrote. Any differing field of any stage (attempt, attemptId, status, errorCode, fingerprints, heartbeatAt, an added stage, sourceFingerprint) is a `conflict`. `expected = null` over an existing file is `conflict`. N processes each performing load + CAS-save increments end with exactly the acknowledged count.
3. **ABA is not detected, by design.** A stored state equal to `expected` is accepted even if it passed through other states in between. This is safe only if every new attempt carries a never-before-used `attemptId`; the planner rejects only an id equal to the CURRENT one. The runner MUST mint a fresh unique id per attempt (BEFORE-WIRING B3).
4. **Corrupt-file preservation.** Truncated or empty JSON, BOM, binary, trailing garbage, JSON of the wrong shape, an envelope for another run id, and a state failing the planner's `validateState` are typed errors on `load` (`corrupt` / `schema-invalid`) and `corrupt-existing` on `save`; the bytes are untouched. A directory or junction at the file path is `not-a-file` / `corrupt-existing`; nothing outside the root is read or modified. A junction at the lock path is `locked`. Load never writes.
5. **Id confinement.** `validateRunId` accepts only `^[a-z0-9][a-z0-9._-]*$`, length 1..64, without `..`, a trailing `.`, or a Windows device base name. Refused on load and save with zero filesystem operations: `..`, separators of both kinds, drive letters, UNC, `a:b`, NUL, Unicode slash look-alikes, over-length, empty, leading/trailing space, reserved names with extensions, uppercase (so `Run1` and `run1` can never share a file on a case-insensitive volume). Distinct accepted ids always map to distinct file, lock and temp names.
6. **Export placement.** The store touches `node:fs`/`node:crypto` and must not be reachable from browser-side code. Nothing under `packages/core/src/domain` may import it. Today apps/web has no `@lkb/core` dependency or import (verified), so the root-index export is not a live defect; before any web code imports `@lkb/core` values, or the store is wired, it must be exported through a Node-only entry (or imported by path), not the root index (BEFORE-WIRING B2).
7. **Lock.** Mutual exclusion across processes via exclusive `<id>.run-state.lock` around check + rename; a held lock = `locked`, nothing written. Released in a finally after success and after every failure.
8. **Lock recovery (met by t050-run-state-stale-lock-recovery, cycle 0 PASS).** The lock body is `{token,pid,host,at}`. Rules and bounds, all measured: (a) owner on THIS host and the OS says the pid does not exist (ESRCH): taken over at once, any age; (b) owner unverifiable (other host, probe `unknown`, empty / unparsable / oversize body, host string differing even by case): taken over only when older than `staleMs` (30 s; `>` strictly, age from `at`, else file mtime, a future `at` is never old); (c) live owner on this host (pid exists, EPERM counts as alive): never taken over below `liveCeilingMs` (1 h; pid reuse bound), displaced above it; (d) this process's own pid: taken over only after `staleMs`. Takeover = claim file `<lock>.claim.<dead token | hash of the unparsable bytes>` created with `wx` (one winner), re-read + re-judge, `rename(claim, lock)`, confirm by token; a claim abandoned by a dead taker is judged by the same rules and removed; the lock is never absent and a possibly-live lock is never moved. Every save re-checks its token immediately before the data rename and refuses (`locked`, nothing written) if displaced. Orphan `<id>.run-state.json.<uuid>.tmp` files of the same run are reaped only after a successful takeover. A crash at ANY step leaves nothing that outlives the bound: `now` when the owner reads dead, `staleMs` behind an EMPTY lock/claim (create-then-write is two steps; ISS-RUNLOCK-001, low), `liveCeilingMs` when a dead owner's pid has been reused. PRECONDITIONS (stated, not enforced): P-R1 no writer is suspended for longer than `liveCeilingMs` (or `staleMs` when its lock reads unverifiable) INSIDE a save; if one is, the stalled writer is stopped by its token re-check or, when it stalled after the re-check, only because the taker reaped its temp file: a failed reap unlink lets it overwrite the taker's newer state while returning ok (ISS-RUNLOCK-003, medium, before-wiring). P-R2 one PID namespace and one hostname per root (a root shared across hosts or containers is judged by age alone). P-R3 operators never delete a lock by hand while a writer may be running. P-R4 liveness probe valid on this host only; the system clock does not step forward by more than `staleMs` mid-save.
9. **Contention errors (met).** EPERM/EBUSY/EACCES creating OR reading the lock while the path exists (delete-pending on Windows) is `locked`, never `io-error`; the same codes with the path absent are retried 1.5 s, then thrown. 3 real processes x 60 load+CAS increments end at counter 180 with zero `io-error`.
10. **Tests must kill:** CAS removed, lock not taken, direct write instead of temp + rename, corrupt file overwritten, `expected = null` overwriting, id validation removed, error swallowed as success, lock released before rename, fsync skipped, lock never released, reserved names allowed, temp in another directory, non-canonical revision; and for the takeover: dead-pid check inverted, unverifiable treated as dead, stale comparison wrong way or at the boundary, ceiling removed, own-pid rule removed, token re-check removed, claim not exclusive, confirm-by-token removed, re-read/re-judge skipped, release without token check, abandoned claim never reaped, reaping on every save or without the name/prefix check, host comparison removed, empty body treated as free, future `at` believed. (Checker cycle 0: 23 of 24 killed; the survivor, a transient read error mapped to "absent" instead of "unreadable", is outcome-equivalent: both end `locked`.)

## Unverified
Durability across power loss (no directory fsync; the file fsync precedes the rename, confirmed by call order only); network or UNC roots; a root that is itself a junction (trusted).
