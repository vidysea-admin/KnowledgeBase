# Contract — t050-run-state-store (T-050 slice 2, file-backed RunState store)

> Ground truth for `packages/core/src/run-state-store/`. Written by the checker; the maker never edits it. Data-write class, never round-capped. Scope: unwired; single machine; local filesystem; in-process and same-host multi-process concurrency; durability across power loss unverified.

## Security property
An acknowledged `save` is never lost or silently replaced, a reader never sees a partial or zero-length state file, nothing is written, read or deleted outside the configured root, and a corrupt or unrecognised state file is never overwritten or deleted by the store.

## Criteria
1. **Atomicity.** Every write is: exclusive-create temp file in the SAME directory as the target, write, fsync the file, close, rename over the target. A reader loop in another thread over 200 overwrites of 200 kB states sees only complete valid documents (never empty, truncated or absent). On any failure (write, rename) no temp file and no lock is left and the old file is byte-identical. The target is never unlinked before the rename.
2. **CAS.** `save(runId, expected, next)` succeeds only if the stored state's canonical revision equals the revision of `expected` (`null` = the file must not exist). The revision is key-order independent. A state obtained from `load` always succeeds as `expected` when nobody else wrote. Any differing field of any stage (attempt, attemptId, status, errorCode, fingerprints, heartbeatAt, an added stage, sourceFingerprint) is a `conflict`. `expected = null` over an existing file is `conflict`. N processes each performing load + CAS-save increments end with exactly the acknowledged count.
3. **ABA is not detected, by design.** A stored state equal to `expected` is accepted even if it passed through other states in between. This is safe only if every new attempt carries a never-before-used `attemptId`; the planner rejects only an id equal to the CURRENT one. The runner MUST mint a fresh unique id per attempt (BEFORE-WIRING B3).
4. **Corrupt-file preservation.** Truncated or empty JSON, BOM, binary, trailing garbage, JSON of the wrong shape, an envelope for another run id, and a state failing the planner's `validateState` are typed errors on `load` (`corrupt` / `schema-invalid`) and `corrupt-existing` on `save`; the bytes are untouched. A directory or junction at the file path is `not-a-file` / `corrupt-existing`; nothing outside the root is read or modified. A junction at the lock path is `locked`. Load never writes.
5. **Id confinement.** `validateRunId` accepts only `^[a-z0-9][a-z0-9._-]*$`, length 1..64, without `..`, a trailing `.`, or a Windows device base name. Refused on load and save with zero filesystem operations: `..`, separators of both kinds, drive letters, UNC, `a:b`, NUL, Unicode slash look-alikes, over-length, empty, leading/trailing space, reserved names with extensions, uppercase (so `Run1` and `run1` can never share a file on a case-insensitive volume). Distinct accepted ids always map to distinct file, lock and temp names.
6. **Export placement.** The store touches `node:fs`/`node:crypto` and must not be reachable from browser-side code. Nothing under `packages/core/src/domain` may import it. Today apps/web has no `@lkb/core` dependency or import (verified), so the root-index export is not a live defect; before any web code imports `@lkb/core` values, or the store is wired, it must be exported through a Node-only entry (or imported by path), not the root index (BEFORE-WIRING B2).
7. **Lock.** Mutual exclusion across processes via exclusive `<id>.run-state.lock` around check + rename; a held lock = `locked`, nothing written. Released in a finally after success and after every failure.
8. **Lock recovery (NOT met; before-wiring).** A holder killed while holding the lock leaves a permanent lock and blocks that run's saves (ISS-RUNSTORE-001). Required before wiring: automatic recovery under the t037 takeover guarantees (G1 never two holders; age AND pid ESRCH; no moving of a live lock) or alerting plus runbook; orphan temp files reaped.
9. **Contention errors.** EPERM/EBUSY/EACCES on lock creation under contention must surface as `locked`, not `io-error` (ISS-RUNSTORE-002; before-wiring).
10. **Tests must kill:** CAS removed, lock not taken, direct write instead of temp + rename, corrupt file overwritten, `expected = null` overwriting, id validation removed, error swallowed as success, lock released before rename, fsync skipped, lock never released, reserved names allowed; plus (currently surviving, ISS-RUNSTORE-003) temp file in another directory and non-canonical revision.

## Unverified
Durability across power loss (no directory fsync; the file fsync precedes the rename, confirmed by call order only); network or UNC roots; a root that is itself a junction (trusted); reaping of stray `.tmp` files.
